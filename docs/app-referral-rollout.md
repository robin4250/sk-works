# SKOアプリ紹介招待（社員初回登録とは別）

## 実装した入口

`AppReferralPage(repository: AppReferralRepository(client))` は本人の紹介画面。
`master: true` はマスターのSKO ID管理・招待記録・ランキング・配布設定。
友達追加側は `friendInvite: true, initialName: name, initialPhone: phone` を渡す。
専用の履歴を別保存せず、同じ紹介招待RPCでsource=`friend_add`を記録する。
SMS案内は「SKOアプリからの友達追加です」、履歴は「友達追加経由」。
既存ユーザーとの友達関係成立を紹介による新規登録として集計しない。
ホーム等の入口は `app_referral_snapshot.can_invite` が true のときのみ表示する。
サーバーは全呼出し時にもアカウント・会社所属・機能設定・権限を再確認する。
初期値は機能OFF・一般公開OFF。管理者はowner/admin（managerを含めない）。

名前・国内電話番号から招待番号付きSMS本文を作る。送信ボタンでSMS作成画面を起動する。
履歴は「招待を準備」「SMS作成画面を開いた（送信・配達未確認）」を明示する。
送信完了・配達済みとは表示しない。招待された番号が実ユーザー本人だと断定しない。
履歴は本人のみ。マスターのみ全体履歴とランキングを閲覧する。
日付はサーバーUTC保存、画面はJST。配布URL未登録時は送信を無効にし理由を表示する。
既存の従業員用QR・一時認証情報は本文にも紹介テーブルにも保存しない。

## 未接続（公開・完成として扱わない）

- 起動後の新規登録と招待先本人の検証は未接続。電話番号の手入力一致で確定しない。
- 既存Auth/signup/社員招待処理は変更していない。
- 最終紹介者の確定と登録済み紹介元の不変化を行うtrusted onboarding処理は別途必要。
- 一般クライアントへ紹介元確定・ポイント付与APIは公開しない。
- ポイント付与数・用途は未決定で、NULL（未設定）のまま。金額入力欄は設けない。
- マスター通知ON/OFFは保存するが、登録完了イベントとの接続は未完了。
- プロフィールへの獲得ポイント表示、通常ユーザー向けホーム入口は統合作業が必要。Master入口は以下の節のとおり接続済み。
- TestFlight URL自体を作成・推測せず、正式URLをマスターが登録する。

## 登録確定処理に必要な条件

1. 本人確認した登録者と招待先をサーバー側で結び付ける（未検証電話番号は不可）。
2. 登録前の最終の招待者を選ぶ。社員初回QRと既存ユーザーへの連携申請を除外する。
3. 受信者IDで一意にロックし、再登録通知・再試行・登録後の再招待でも二重付与しない。
4. 登録時の紹介者・会社・日時を保存し、設定変更で過去の帰属を変更しない。
5. ポイント数が未決定の間は人数のみ集計する。決定後は付与台帳とプロフィールへ反映。
6. 通知OFFでも記録は保持。通知ONなら既存通知説明ページへのリンク付きで配信する。

本番DBへ未適用。機能をONにする前にテスト環境で権限・二者登録・再試行を確認する。

## SMS起動・記録の再試行

同じ画面で同じ名前・電話番号・紹介経路を再試行する場合、起動失敗時は準備済み招待IDを再利用します。SMS作成画面の起動後に履歴保存が失敗した場合は「履歴を更新」で記録だけを再試行し、SMS作成画面を重ねて開きません。失敗後も一覧を再取得するため、サーバーに保存済みの準備履歴を確認できます。送信完了・配達済みとは表示しません。

再試行状態はページ内のメモリに限定します。画面を閉じた後の送信再開は未実装です。ログイン利用者が変わった場合は準備内容を再使用しません。実SMS送信・登録確定・ポイント付与・新たなDB経路は追加していません。

## Masterからの入口

「設定」→「Master 機能設定」→「SKOアプリ招待・紹介管理」から、既存の設定・全体履歴・ランキング画面を開けます。Master専用snapshotで毎回権限を確認し、遷移先も既存Master本人確認画面で保護します。機能OFFでも設定入口は残し、招待入口はenabled/can_inviteを満たす場合だけ表示します。正式配布URLが未登録なら理由を表示し、実際のSMS作成は既存画面で無効になります。

今回の完成範囲はMasterからの確認・設定・招待入口です。通常owner/adminおよび一般公開対象ユーザー向けの入口は未接続です。本人検証付き新規登録、最終紹介元確定、ポイント付与・登録完了通知も別残件で、今回実装していません。実SMS送信や仮URL登録は行いません。

## 本人用入口

設定の共通個人設定位置に「SKOアプリ招待・自分の紹介履歴」を追加。owner/adminも一般公開対象も、既存app_referral_snapshotのcan_inviteを使い、自分のAppReferralPageへ遷移する。ローカルroleで許可を増やさず、開く直前にサーバーの利用状態とログイン主体を再確認する。OFF・権限不足・取得失敗は説明して遷移しない。URL未登録時は履歴のみ確認でき、既存送信ボタンは無効のまま。Master設定/全体履歴とは分離する。本人検証・紹介元確定・実ポイント付与・登録完了通知は別残件。実SMS送信/本番SQL適用は行わない。
