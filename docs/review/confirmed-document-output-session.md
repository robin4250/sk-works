# Confirmed viewer and native output session — candidate

This successor binds the production Supabase confirmed-document repository at entry to the existing FormSession. Confirmed RPCs keep the same captured bearer and gate dispatch/late responses on SDK history, the shared Auth mutation gateway/logout intent, token/SID, lifecycle, and disposal. Shared Auth code and the financial generator transports are unchanged. Lost acknowledgements remain unknown; cancellation does not establish server rollback or instantaneous JWT revocation. Existing consent/receipt and current server membership/permission checks remain in place.

After the existing full approved-evidence validation, the output factory additionally checks the exact viewer render envelope. Its company is `raw.company_id == scope.p_company_id`, never the foreign `evidence.body.issuer_company_id` of a received document. Local/document ID, revision, kind, actor and archive side remain bound. The returned child session includes that descriptor as its target and is unusable if entry history already changed. Changing/restoring an observed target cannot revive it.

Issued and received production pages keep that same child scope through the new format route and existing print/share. Entry invalidation immediately removes retained PDF views. A child route by itself is not a native-print lease. The optional `onNativeOutputChanged` signal covers only the actual owned native handoff; arbitrary inactive/background state retires the viewer. Scope and visibility are rechecked when native output returns. Existing legacy original bytes, bank/company/seal snapshots, approval bodyhash and renderer selection are unchanged. Generic injected test repositories retain their original actor/token test behavior; they do not prove production Auth admission.

The dedicated tests use the actual pinned SDK and repository HTTP wire with synthetic signed-envelope fixtures, plus actual approved viewer/child widgets and the pinned printing platform boundary. They exercise cached replay, fresh same/different SID, real SDK refresh event, pre-SDK logout intent, held response, target changes, foreign issuer/viewer distinction, and owned native visibility. They are not real GoTrue/production membership or physical-iPhone/printer evidence. Source readiness and all CI results must be recorded separately; no deployment, production SQL, feature activation or delivery is performed here.
