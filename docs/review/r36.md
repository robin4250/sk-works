## ① ログインを保ったまま確認

- [ ] 会社名・本人名・権限表示と、既存出勤／請求書等が従来どおり見える。
- [ ] 設定の本人確認情報で、使用済みのGoogle連携が表示される。電話番号・
      Appleは連携確認済み表示がある時だけ記録し、連絡先の登録だけで認証済みとしない。
- [ ] アプリを終了→アイコンから再起動して同じ会社・本人・データへ戻れる。
- [ ] Masterを既存のFace ID＋第2パスワードで開ける。新しい専用モードの有効化、
      パスワード変更、端末ロック／登録解除は行わない。
- [ ] Masterから戻る→アプリを背景へ→復帰するとMasterには再認証が必要になる。
- [ ] 復旧メール2件が保存済みであることをアプリ内で確認する。メール・コード・
      パスワード・トークンをチャット／Issue／公開写真へ記録しない。

## ② 準備が整った時だけ、本人がGoogleで再ログイン

先に担当者が、対象ReleaseのGoogle入口・許可callback・既存会社確認の検査結果と、
①の保存結果を確認する。現在使っているGoogleアカウントを本人が識別でき、
再ログインできない時の対応先が確保できてから実施。準備不足ならここは未確認のまま①を保持。

- [ ] 本人が明示的にログアウトし、正しいログイン画面にGoogle入口が見える。
- [ ] 「登録済みのGoogleでログイン」から従来と同じGoogleを選ぶ。別Google・
      新規会社作成・社員の新規登録は選ばない。
- [ ] 認証画面を開いただけでは成功扱いしない。会社確認が終わりホームへ戻る。
- [ ] 同じ会社・本人・権限・既存出勤／帳票へ戻り、終了→再起動でも保持される。
- [ ] 担当者が許可された読み取りで、前後の本人UID・会社所属・役割・元データIDが
      同一と確認する。見た目が同じだけでは同一IDの証明にしない。値は非公開で保存。

**異常時：** 新規登録画面・別会社・データなし・予期しないSMSが出たら操作を止め、
画面名と時刻だけ報告。アプリ削除、アカウント作成、会社再登録、パスワード推測の連続入力はしない。
#1204を含む検査済み版では「本パスワードを忘れた方」はSMS送信せず説明を表示する。
これはFace IDによるログアウト後の本パスワード復旧が完成した意味ではない。

## ③ Masterと二重メールの復旧は別の確認

- [ ] ②の後も既存Master・Face ID・第2パスワード・復旧メール設定が維持される。
- [ ] 2台目の正規端末と復旧準備ができた時だけ、既存の緊急復旧導線を本人が開く。
      現在の唯一の利用可能端末をロック／解除して未信頼状態を作らない。
- [ ] 既存本人確認後、2つのメールに別々のコードが届くことを確認する。
- [ ] 両方の正しいコードがそろった時だけ既存処理で信頼済み端末登録が成功する。
      1つだけ・不一致・期限切れを成功扱いしない。意図的な失敗の連続試行はしない。
- [ ] 元iPhoneの利用と会社・Master権限が維持される。登録後も端末を勝手に解除しない。
