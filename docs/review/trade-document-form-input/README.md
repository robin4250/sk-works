# Typed formal contract save guard — review only

No production application, rollout change, new API grant, or document delivery is authorized here. This independent successor requires the exact confirmed-terms guard from PR1595. Apply sequence: current core → optional frozen partner bank candidate → confirmed terms → this guard. Reapplication or the wrong order fails closed. The existing original source/save delegates, financial gross/tax constraints, 16KiB limit, CAS, finalization, company seal and known immutable legal reference remain delegated unchanged.

`server-save.sql.review-only` adds strict schema1/9-row validation when `form_fields` is explicitly present, preserving absent legacy input on existing originals. Missing/null/extra keys, invalid dates/ranges/types/row counts and inconsistent no-payment data reject. Once a saved namespace exists it cannot disappear; an explicit valid empty value is still a normal user edit. Quantities/row amounts never calculate or overwrite source totals. The private pure validator is invoker-only and postgres-only; authenticated clients retain only the existing canonical save API.

On a source change, a legacy saved payload lacking original canonical party identity cannot prove that its historical counterpart is still the current one. Such a resave refuses rather than transferring its snapshot by display name. For an order with an existing authoritative bank snapshot, the actual same-company payment parent is locked FOR SHARE and its canonical partner ID must equal that immutable snapshot. Same-name/different-ID and missing links refuse; a new bank-master version never silently replaces the saved bank. This is additional protection; it does not create a new historical identity or erase the old document.

The client session lease prevents dispatch after observed SID/token/logout-intent/lifecycle changes and refuses late UI success. Existing core save routes do not all lock live `auth.sessions`; client cancellation does not prove an in-flight server transaction rolled back or an old JWT was immediately revoked. A sent request with lost acknowledgement requires reauthentication and official readback, never blind retry.

The dedicated fixture executes actual repository migration and review SQL in disposable PGlite/Postgres17 for both accepted predecessor sequences. It checks malformed input denial before any save, explicit 9-row values without financial inference, immutable references, byte-bound enforcement, original definition/attribute retention, private-helper denial, current management admission, canonical partner changes, and reapplication denial. These synthetic SQL tests are not production Auth, signed-iPhone, printer or delivery evidence. Authoritative missing TEL/FAX source extension is separate.
