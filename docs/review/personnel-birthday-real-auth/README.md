# DOB canonical API: genuine authentication connection (test only)

This lane covers the missing real-GoTrue/PostgREST connection to the saved DOB canonical save/approval functions. It adds only a disposable runner, a strict fixture adapter, new assertions, this document and dedicated CI. No existing four-function definition, Auth/RLS/DOB source, UI or deployment is changed. No production endpoint, records, passwords, tokens or employees are used.

The established company-checkout local-stack setup/cleanup is reused by exact unique anchors, including local-host/port checks and refusal of hosted Supabase credential environment variables. The old 60-second expiry experiment is removed for this different purpose; the normal local JWT lifetime is retained. All users/identities/sessions are created through genuine GoTrue admin/password HTTP APIs, not INSERTs into Auth tables.

The personnel foundation is pinned to immutable `personnel_write/verify.mjs` SHA256. Only its setup prefix is reused; the old34/30/39 suites do not run. Strict exact anchors remove its synthetic `auth.uid`, Auth tables, identity/user INSERT loop, role creation and fixture-actor setter, and inject the actual GoTrue user IDs explicitly. Saved application tables, policies, canonical function definitions/grants and the existing permission migration remain. The adapter rejects direct Auth writes/DDL and fixture/JWT actor GUC setters. The two frozen DOB installer source hashes and all four function attributes are verified; this fixture setup is not a new atomicity proof (PR1603 covers that separately).

The original saved `private.check_account_access` pre-request hook is configured only on the isolated local PostgREST role and its existing sentinel RPC must prove it ran before application assertions begin. Missing/changed prerequisites fail the test; no stub capability, fake response, synthetic successful save or fallback is substituted. An authorized public personnel HTTP read supplies the exact worker/company/contract and the existing client's payload key mapping supplies save input.

New cases cover nullable DOB, marker-omitted no-op without mutations, self proposal keeping the approved DOB, self/foreign approval denial, a different configured same-company administrator approving the actual request, unrelated same-company/foreign target denial, and an old-client birthday omission through another real HTTP proposal/approval that preserves the approved date. Explicit null clearing and old-client no-op preserve the nullable contract. Denials retain all synthetic business/pending/approval/notification rows; original `auth.uid`/`auth.jwt` definitions and attributes remain unchanged.

## Session boundary, deliberately not strengthened

The saved canonical personnel API and its account hook do not call the newer live-SID helper. This test does not add a SID check, password proof, gateway or new authorization claim. At the end it logs out the genuine self session, verifies that GoTrue removed that session, and observes a **no-op** request with the still-unexpired JWT. If PostgREST accepts it, the response must be unchanged and no business data may move; if the API rejects it as unauthenticated, that observation is recorded separately. Neither outcome establishes a new canonical live-SID revocation guarantee. The result explicitly reports `live_sid_guarantee_added:false` and the observed old-JWT acceptance boolean.

Actual local CI must succeed before this connection is called verified. Even success is a synthetic application-foundation/authentication integration proof, not the full current production schema/RLS stack, active-session revocation protection, protected backup recovery, deployment/GRANT/flag authorization, public distribution or iPhone evidence. Bank/document/exemption OFF state and all existing original-data protections remain outside this test's production write scope; no production operation occurs.
