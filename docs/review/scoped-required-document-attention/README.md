# One canonical document-evidence receipt

Successor to the explicit-company read-only contract. The separately authorized global exemption switch is now ON; this source performs no feature activation or individual decision/event write. All other production DDL approval/HOLD conditions remain.

The scoped endpoint returns every active required requirement by immutable requirement ID, with saved/missing/unknown/exempt states, separate counts, scope, status label and a saved-evidence key. Exempt records remain visible as exemptions and outside the required denominator; they are never submitted or saved evidence. Same-name requirements in different scopes retain different IDs and counts. No attachment paths, bank account values or exemption reasons are returned.

Guide and attention use this same validated receipt and DTO. The production guide no longer independently reads bank/photo metadata or reinterprets a different RLS outcome. Invalid, missing-capability, expired-session, wrong-company and malformed receipts remain unknown/unavailable with no legacy-RPC fallback. A new company requirement appears in both consumers from the next receipt. Existing legacy pure-evaluator tests remain, while their superseded SDK wire tests are replaced by canonical wire and actual SQL-to-Dart receipt tests.

Authorization remains the five captured actual generic helpers plus the explicit-company member/unique active worker checks. The old no-argument RPC and helper bodies/ACLs are unchanged. The new endpoint remains authenticated-only, with no PUBLIC/anon/service_role or grant-option access. No table grants, original/document/payroll writes, old-SID rewrites or RLS changes are performed.

Native/PGlite tests use synthetic Auth rows and claims, never real GoTrue or signature verification. Native generated synthetic receipts are parsed by the shared Dart DTO and drive both guide and attention in CI. This source is not production application, signed Release, installation or real-device proof. The person's birth-date backend and multi-company edit-route selection remain separate scopes.

Apply only after a fresh complete catalog/independent review and explicit production approval, with coordinated DDL writers. A lost COMMIT result requires read-only receipt inspection. No blind retry, automatic old-function restoration or data restoration is permitted.
