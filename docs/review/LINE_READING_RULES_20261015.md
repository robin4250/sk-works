# LINE 初期設定・読み取りルール

取込済み原文を頻度順で語句集計し、右側の振り分け先から現場・氏名・手当・勤務区分・残業・早出・対象外を選択する。
登録済み現場・従業員の完全一致と既知の残業/早出だけを自動候補にする。複数候補は未設定、保存した手動ルールを優先する。
現場/従業員は登録済み対象の名称を選択可能。原文や出典は変更しない。

## 保存と権限

ルールはグループ単位、既存 LINE 利用/グループ参加/会社請求管理権限を毎回確認。
私有テーブルは RLS と権限剥奪。公開 RPC は invoker、私有 definer 内で既存 line_import_access を呼び出す。
revision 競合防止・初回挿入の排他・入力型/長さ/重複検査。確定帳票や給与には変更しない。

## 検証

- pure Dart 4 cases: 頻度・原文不変・自動候補/曖昧・手修正/確定/出典保持
- isolated PGlite: 保存/再読込、revision競合、重複、別グループ、閲覧専用、匿名拒否
- Supabase changelog と functions docs を確認。新本番適用なし。

## 接続残り

- #1054 の単価一覧 callback へ新画面を接続済み
- 次回取込の新規候補へ現場・氏名の保存aliasを適用。登録済み参照名が一意にIDへ解決できる場合だけ反映。保存済み同fingerprint行は修正markerが無くても保持。原文不変。
- 自動予測初期値も保存、手動指定優先。
- 手当・勤務区分・独自残業語・対象外ルールの取込適用は未完了（画面へ準備中と表示）。
- 全分類の具体対象 ID/標準値との検証、再適用プレビューと明示確定
- 過去表や手修正の再適用、原文へ戻る導線、専用機能 ON/OFF
- Flutter/iOS CI、実機操作、本番 migration は未完了

過去表の再集計・全分類適用・数値予測・正式請求完了とは案内しない。辞書の未適用migrationだけにMaster専用guardを追加。既存import access本体は不変更、本番適用なし。会社owner/admin/managerだけではRPC直呼び不可。実import/access定義を読込む隔離fixtureで境界を検証。

## 残分類・仮時間の候補解釈（別段階）

- 対象は新規未確認候補のみ。同fingerprintの保存済み行、手修正、確認済みは維持。原文へ文字置換しない。
- 残業・早出の明示値は実数、語句だけなら仮1時間。assumed_fieldsに対象field/value/reason/source_message_idを保存。
- 月別表の仮数値を押してその欄だけ修正でき、当該metadataだけ解除。他の値・仮状態・出典は保持、confirmedは自動trueにしない。
- 通常の確認操作でも仮値の採用を明示確認。仮metadataがある間は確認済集計から除外し、正式保存の確認条件を満たさない。
- 手当はallowance_names、勤務区分はday/night/holiday/holiday_nightへの明確な対応のみ。対象外はtoken単位で、行を削除しない。
- 同一現場でも従業員名を照合して残業を個別解釈。複数の現場だけの報告から一意に選べない場合は未確認のまま。
- 既存JSONB保存契約でstructured metadataが保存・再読込・片側補修されることと、未確認の正式preview拒否を隔離検証。SQL変更なし。

残件：手当回数の個別数量、区分の曖昧表現・自由文推測、既存保存行へ辞書を再適用するプレビュー、server側対象ID辞書契約、同一人物の重複報告の選択。仮数値は勤務語のある残業・早出1時間に限定し、人工や単価を無条件に作らない。

## 保存済み未確認行への再適用プレビュー

現場・氏名aliasだけの最小再適用。月別表で未保存変更を保存後に入口を開き、項目ごとに前後確認→採用→採用項目だけ保存。正式確認は自動で進めない。

- 新規自動生成行だけreading_origin.kind=automaticとsource_fingerprintを記録。markerのない旧行は推測で自動扱いせず保護。
- プレビュー時に現存原文のfingerprintとの一致も確認。確認済み・manual由来・手修正flag・manual:行・除外行は対象外。
- 仮値セル補修・通常の行編集・除外checkbox・再適用採用の各入力でmanual由来に変更。再取込は同fingerprintの由来を保持。
- 一意に解決できない登録先は保留。登録一覧にある一意な対象を選び直せるが、同名候補を見分ける情報がない場合は既存個別編集へ案内。
- 採用したnameと対応identity/customerだけ変更。数量・原文・出典・他の仮metadata・未採用fieldを維持。revision競合は保存拒否し再読込。
- 新規SQLなし。既存JSONB保存で由来metadata保持を隔離検証。

残件：旧行の由来確定、時間・手当・勤務区分への保存済み再適用、同名登録先の詳細照合。旧行は個別編集を使用し、判別不能なまま一括上書きしない。
