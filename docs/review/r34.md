# R34: reuse the saved signed-out recovery guidance

Baseline main `502ccfb448b0efd51ca78fa5053727be13e2a5b7`.
Reuses PR1157 `732c81e79d8ce0f556627b3d62033e96d1a660e5`; this is not a new
authentication or recovery authority. That candidate was held while the owner's
Google entry was missing. Google access was subsequently restored and the owner
reported successful access. Apple and phone-password real-device loops remain
unverified; this change does not label them complete.

The existing signed-out forgotten-primary entry no longer offers an SMS reset or
accepts a replacement password. It distinguishes primary login from signed-in
secondary Face ID reset and explicitly points existing Google users back to the
existing Google entry. It does not infer phone credentials from a Google profile.
The phone/password login and employee QR remain. The Google flow, callbacks,
fixed bearer/company-membership validation, lifecycle/generation checks and pending
control guards remain. Secondary setup and all later source is byte-identical.

Only the reset-specific repository SMS methods are removed. Initial signup SMS,
verification/resend and separate phone-change code are deliberately unchanged;
these are remaining SMS deprecation work, not a claim that all SMS is removed.
Master/secondary Face ID, two recovery emails, provider settings, role/company
links, server functions and production data are untouched. No new account linking
or credential creation occurs here. Primary recovery remains unavailable on this
page; it is not falsely replaced with local biometric authorization.

History is reused from docs/security/FACE_PASSWORD_ENTRY_MAP_20261017.md in PR1157:
SMS primary recovery was introduced by PR164/176 in September, not proven to have
newly returned at logout. Prior Face reset was identified as signed-in secondary
reset, PR872. The same gate leads to SecureAuthPage after logout. Neither these
facts nor this patch establish a previous Apple login implementation or a working
logged-out Face-only primary reset.

Existing SDK/widget tests are reused. One new behavior test opens the forgotten
page, returns without SMS/update, then completes the unchanged Google session and
membership route exactly once. Actual provider login, signed Release, iPhone,
full restore and TestFlight remain separate evidence. Linux has no Flutter; CI
must succeed before integration. No production configuration change is authorized.
