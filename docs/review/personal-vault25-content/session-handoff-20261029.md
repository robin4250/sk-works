# PDF preview and native handoff lifetime (2026-10-29)

The existing candidate screen previously closed repository Auth history immediately after downloading bytes, then retained those bytes in preview/layout callbacks. The screen now uses `withOwnPdf`: exact read-session history remains alive through preview or native handoff, and every lazy renderer/layout callback obtains a newly checked copy. Auth change/logout/error, owner cancellation or completion terminally closes that in-memory lease. A stuck platform future cannot keep the logical operation/Auth subscription alive after cancellation; late callbacks refuse bytes.

The candidate screen retires its list state on session/token history change or leaving the foreground, including an initially non-resumed/null lifecycle. Its preview child is disposed and only its owned route is removed; a page above it must not be popped. Client replacement also replaces the screen lifetime and ignores late events from the old client. No route exposure or feature activation is added.

This does not recall bytes already handed to the OS/share recipient, erase existing downloaded originals, zero every renderer/plugin copy, prevent OS screenshots, serialize global SDK mutations, or detect SDK changes that emit no history and silently return to the same token. It does not create independent source/privacy attestation or immutable retention. Existing raw repository download API remains for trusted callers; only the existing screen's path changes to a leased handoff. The last synchronous SDK/lifetime check immediately precedes plugin invocation; plugin-internal/OS handoff is not atomic with Auth changes. Physical iPhone share/print/background rendering remains unverified.

New tests exercise actual Supabase SDK logout and same-UID SID replacement after download, retained callbacks after operation completion, defensive copy ownership, cancellation of a never-settling native future, cancellation before handoff, owned-route removal underneath another page, screen retirement after background/resume, and initial paused refusal. Server/Storage replies in these tests are synthetic; they do not establish production authorization/Storage provenance. Flutter is unavailable locally: exact-head focused and combined CI must run before merge. No payroll renderer, calculation, production DB/RLS, stored PDF, original signature or exemption gate changes.
