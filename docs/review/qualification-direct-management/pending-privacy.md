# 資格操作の再試行情報を最小化する

未配布のv1候補はSharedPreferencesへ資格snapshotと入力値を保存していた。この方式は社員配布前の条件を満たした扱いにしない。v2は端末に操作ID・操作者ID・会社ID・対象資格ID・従業員ID・資格種類ID・操作種別だけを保存する。資格番号・発行元・日付・備考・写真path・写真bytes・token・署名を再試行キーへ保存しない。

同じ「保存」操作内で、入力値は非公開サーバー台帳へprepareし、続いて操作IDだけでapplyする。別人の承認や承認待ちは追加しない。prepareは正式資格を変更せず、全snapshot CASと現在の管理権限を確認する。applyはサーバーに固定された同じ本文だけを使い、正式記録・既存履歴・監査を一度だけ変更する。

サーバー本文の有効期間は15分。適用・取消後は直ちに本文をNULLにし、期限切れは毎分のcleanupでNULLにする。ID・対象・操作者・状態のtombstoneは残し、遅れて届いたprepareで閉じたIDを復活させない。別の管理者・別会社は準備済み本文や結果を取得できない。正式適用後の監査は既存の履歴保持方針との照合が別途必要。

cleanup jobの不存在・停止・直近失敗・2分以上の成功実績不在ではcapabilityを有効にせず、新しいprepare/applyを止める。すでに保存された結果のgetと未完了操作のcancelは停止中でも正規権限で行える。実Cronの登録・実行・失敗通知は本番未実施であり、fixtureの成功では代用しない。install-pending-cleanup.sql.review-onlyは既存の同名jobを上書きしない。

actor変化・ログアウトを観測したrepositoryは再ログインで同じactorに戻っても再利用しない。端末に残るのは元actor/companyに結び付いた不透明IDだけで、別actorからの読み取り・再送は行わない。元actorが正規に再ログインした場合だけ、そのIDのサーバー結果を確認できる。端末時刻を理由にサーバーの適用可否を変更しない。

未配布v1のキーが見つかった場合は、新しい通常保存を先に始めない。同じIDの本文をサーバーが受け付けた／既に適用したと確認した後だけ、旧全文キーを削除しIDキーへ移す。通信不明やID不一致なら旧キーを黙って消さず、明示的な結果確認／未完了取消を要求する。本人写真申請の既存キーは変更しない。旧キー移行が未解決の端末を配布前検証の完了扱いにしない。

Native/PGliteはserver prepare/apply、期限・本文消去、取消tombstone、競合、cleanup異常時停止を検証する。Flutter CIは端末キーに個人情報が含まれないこと、応答喪失後のIDのみの復旧、actor切替、旧キー移行を検証する。実GoTrue・実Cron・iPhoneでの完了は別条件で、未達なら候補はOFF・統合保留とする。
