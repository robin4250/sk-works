# 現場別の責任者サイン待ち（候補・未配布）

Base main: `986ac4d51d9c0298d5cd04a6d38d8d373f697094`。

一覧に緑「保存済み」、赤「サイン待ち」を表示する。赤は文字でも状態を示す。
報告者サイン前は「入力途中」、両方の署名があってもdraftなら「確定待ち」。
`サイン待ち`入口は選択中の月・日付に関係なく、現場ごとに保存日報を一覧化する。
保存済み日報IDを保持して既存の編集ページを直接開き、戻った後は一覧を再取得する。
写真添付ページは件数・署名状態に含めず、日報自体を1件とする。

通常日報は既存RLS付きdaily_reportsの読取だけ。署名本文は選択せず、保存済み署名の
null状態で識別する。代表サインは正規の既存署名RPCで保存・検証された形式を前提とする。
既存月一覧へ署名有無のIDだけをページ取得し、誤ってdraftを「保存済み」と表示しない。
全期間の待ち一覧はreport_date/id keysetページ取得、重複・後退・誤statusは失敗として扱う。

訪問日報の既存一覧RPCには最大32日と署名情報不足があるため、別の追加read-only候補
`list_pending_route_visit_reports`を用意した。既存関数・制限は変更しない。
既存account_access_allowed、created_by本人、company_members所属境界を再利用し、
会社・任意worker・前cursor rowの本人/会社/日付を再検証。1ページ最大200件、NULL limit拒否。
戻り値は識別情報・日付・現場・署名有無boolだけで、署名本文を返さない。
新RPC未導入/途中読取失敗時、訪問分の部分ページは表示せず「訪問日報のサイン待ちは未確認」
を明示し、取得済みの通常日報は保持する。全件0件という成功表示へ変換しない。
