# 必要書類設定の重複項目削除

対象は社員資格書類→必要書類→必要書類設定（社内/取引先）のdocument_requirements項目。本人資格写真のPR1320は含めない。

表示チェックis_activeは維持する。項目削除はarchived_atを別に保存し、同時にis_active=falseへ変更する。通常一覧/選択候補/本人新規登録から除外し、削除済み専用一覧から元IDで明示復元する。復元時も非表示で戻す。提出済status・添付・履歴・既送信snapshot・既pendingは削除/付替えしない。export用name mapにはretained_requirementsを使う。both削除は社内/取引先両方の候補から外れる旨を確認する。

unique(company_id,scope,upstream_name,name)は維持し、ON CONFLICT writerを変更しない。削除済み同名を新IDへ再登録せず元IDで明示復元する。標準項目追加も削除済みキーを重複INSERTしない。物理DELETEはstatus/submissionsのFKに影響するため使用しない。

updated_at自動triggerは無いため、company/idだけでなくname/scope/upstream_name/company_template_id/is_required/expiry_required/renewal_reminder_days/is_active/sort_order/created_at/updated_at/archived_at全列のCASを行う。既owner/admin/managerとRLS、account restrictive policyは不変。archive/restore自身はupdated_atも更新する。

新列未導入ではarchived_atの正確なmissing-columnエラーだけ旧readerへfallbackし、checkboxを維持し削除は無効。その他の取得失敗は隠さない。新schema→Release→iPhoneで項目削除/再読込の順が必要。本番適用・実機確認は未実施。

既worker_document_change候補のpreviousはworker_document_statuses専用snapshotでありrequirement全JSONではない。既exchangeはrequirement明示列をdeliveryへコピーし、to_jsonb対象はdelivery/item。列追加だけで既pending snapshotは変更されない。削除対象のis_active=falseは既pendingの承認可否に影響する既契約であり、requestは保持する。復元後に必要なら表示を明示再ONする。

新規書類選択/追加・編集dialogは左右16px余白、max560、全幅content＋縦スクロール。AlertDialogのviewInsets処理を使用しキーボード分を二重控除しない。資格登録popupは統合担当の別所有。

隔離DBfixture成功。Flutter解析/widget/HTTPはremote CIで確認し、local Flutterは起動しない。SQLはreview-onlyで自動migrationへ追加しない。rootは適用前catalog/原本/未使用rollbackと利用後archive保持の条件を確認する。既行値/unique/RLS/権限を変えないadditive DDLのみ。
