# Synthetic saved-payload / SQL / PDF connection proof

The dedicated `connected-saved-sql-pdf` CI job loads `test/fixtures/payroll_transfer/ui-save-equivalent.json` as the same saved-setting shape used by the existing individual settings UI. It does not drive the widget, authenticate a person, use their payroll, or change production. The JSON is inserted into the disposable PG17 settings row, and the existing review-only baseline and candidate sync function bodies run unchanged. The SQL emits the actual saved statement detail for the real, unchanged Flutter PDF renderer; no hand-built replacement detail is inserted between them.

Assertions cover daily allowance registration and attendance basis, existing gross/deductions/net preservation, unchanged overtime, finalized full-row/snapshot preservation after settings/attendance mutations, monthly behavior and amount mismatch refusal. The sync function preserves seeded authoritative gross/deductions/net; this test does not claim it independently calculates all authoritative payroll totals or tax. The numeric sum of actual saved base/overtime/allowances is also checked against those seeded totals. Invalid transfer settings are preserved by SQL but must be refused by the presentation function with visible warning rather than guessed attribution. Original Maps and finalized saved snapshots are unchanged by rendering.

PR1562 preserved the monthly stale-enabled warning as a regression witness after daily-to-monthly settings changes. The successor warning-only change retains the same four SQL cases and saved JSON, and changes only the monthly PDF expectation: known valid non-daily settings remain inapplicable without a false error. The invalid daily case still warns, and all monthly monetary amounts and allowance rows remain intact. See `NON_DAILY_WARNING.md`.

The dedicated test lives at `tool/tests/payroll_position_transfer_connected_test.dart`, outside the standard `test/` discovery tree, and is explicitly invoked only by its dedicated CI job. Standard `flutter test` does not require the dedicated Native SQL/font environment. The dedicated test requires Native SQL output, a real Japanese font and actual PDF text extraction; missing evidence fails rather than skips. All fixture identities, earnings and company names are fictional. SQL runs in one transaction ending in rollback against the fixed localhost disposable CI service. Neither existing SQL/function bodies nor the payroll renderer are modified. Existing UI and PDF tests remain complementary evidence; this job closes their previously disconnected saved-data seam. No production installation, source data mutation, person-specific activation or iPhone verification is performed.
