# Collector signed transport: native PostgreSQL verification slice

This change adds only a CI wrapper and unique workflow. The five original signed-transport candidate files remain unchanged. The source-integration baseline is main `351adf796ca8cbf5a32d4766b017b6afd0d302dd`, including PR1336's successful 12 Node and 14 PGlite/loopback checks. Those earlier results are retained, not newly claimed as native execution.

The wrapper invokes the unchanged `collector_signed_transport_candidate/integration.mjs` with main's existing `collector_storage_pg_adapter.mjs` as its PGlite-compatible adapter. That adapter independently requires server_version_num in PostgreSQL17, the existing loopback-only fixture guard and an empty catalog. The wrapper also requires Linux CI, the fixed local disposable destination, no hosted project credential environment variables, unchanged candidate manifest hashes, and exact adapter/guard Git blobs. It never provisions a hosted role or connects to production.

The original integration has literal PGlite/native=false fields in its JSON report. They are not evidence of the selected adapter. This wrapper captures that report, requires all 14 checks and the exact native adapter to succeed, and emits a separate native receipt that explicitly states the original labels are legacy literals. No original code or manifest is rewritten to relabel a result.
