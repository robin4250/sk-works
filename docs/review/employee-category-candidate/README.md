# 従業員区分（build 24 候補）

## 操作

社員データに「区分」を設け、会社ごとに正社員・派遣社員・アルバイトを選択肢として提示する。管理者は選択肢を追加でき、社員一覧には保存済みの区分名を表示する。既存社員には区分を自動設定せず「未設定」と表示する。区分は職種・権限・所属・給与方式とは別の項目とする。

## データと権限

社員一覧は `PeopleCloudRepository` を経由し、個人情報閲覧には `employee_personnel_view`、編集には `save_worker_personnel_profile` と承認申請を利用している。本番スキーマの `workers` および `worker_personnel_profiles` に区分列はない。既存 `affiliation` は社員／協力会社の区別なので流用しない。

会社単位の区分マスタと社員ごとの区分IDを用意し、会社IDを含む複合参照で他社の選択肢を紐付けられないようにする。名前の重複・空白・過長を拒否する。既定の3区分は会社内だけに存在するものとして、初期化を冪等に行う。使用中の区分の削除・名前変更は履歴に影響するため、削除ではなく使用停止とし、既存の表示を維持する。既存社員や給与情報には一括変更を行わない。

閲覧・編集・承認は既存社員データのアクセスモデルを調査して同等の境界を適用し、社員区分を通じて非公開社員の存在が漏れないようにする。区分の追加や社員への割当は変更者・時刻・変更前後を記録する。社員個人情報の直接保存・承認ルートに変更が必要か、本番定義を確認してから実装する。署名、社員ID、会社紐付けは変更しない。

## 検証条件

異なる会社の区分を参照・設定できないこと、匿名・一般社員・管理者それぞれの閲覧と変更範囲、認証失効後の操作拒否、承認ルート、重複・同時変更、使用停止済み区分を含む過去表示、旧アプリとの互換性、既存社員が未設定のまま表示されることを合成データで検証する。データベースへの適用とbuild 24への採用は、build 23とは別の作業として実施する。
