# Apple key and ingress candidate

Independent, not deployed; the separate wired handler is a review-only candidate. The key resolver fetches Apple's official HTTPS JWKS endpoint only, rejects redirects, private RSA material, invalid/duplicate key IDs and oversized bodies, coalesces concurrent refreshes, caches up to five minutes, and applies a hard deadline even when an injected network adapter ignores cancellation. Expired keys are never used after refresh failure. Unknown keys fail closed until refresh; this may delay legitimate key rotation by at most the configured cache period.

The original rate-gate adapter is only a fail-closed contract. A separate shared PostgreSQL candidate and review-only handler are described below. It must derive actor/session after GoTrue verifies the exact bearer, not from a client field. A verified trusted ingress limit is separately required before authentication; forwarded IP headers from the caller cannot be trusted. Neither a per-process counter nor a bare boolean demonstrates durable enforcement. Thresholds, policy for lockout, expiry and alerting require operational review before activation.

Existing reviewed root HOLD reconciliation and bounded redaction are in PR #1420; this candidate does not duplicate or bypass them. Real managed ingress, durable storage, resolver network deployment and direct-GoTrue bypass protection, actual Apple credentials, and iPhone verification remain incomplete. No provider, Auth, key, data, or production configuration has been changed.

## Durable actor window candidate

A new shared PostgreSQL counter serializes attempts by verified actor, across sessions and app instances. It calls the existing live-session and Google/company context helper in the same database transaction. Candidate configuration is strictly OFF; the proposed five attempts per fifteen minutes is a review parameter, not an approved production policy. Rejections return normally so their counter commits; unknown RPC outcomes fail closed and may conservatively consume an attempt. After the fixed window expires, a valid same-account session automatically starts a new window. A client session cannot reset the actor window. The counter is private, service-only and does not change Auth identities, passwords, memberships, or existing sessions.

The composed review-only native handler validates exact GoTrue bearer first, checks the shared counter second and only then verifies Apple or the primary password. Four existing safety gates plus a new `sharedRateReviewed` flag must be true. The supplied code remains unconnected to a deployed endpoint. PostgreSQL fixture tests use an explicitly synthetic Auth context; real GoTrue, permission, ingress, backup/unused restore, retention, false-positive administrative recovery and multi-instance production behavior are not proven. The verified-actor counter cannot protect requests before bearer verification; trusted pre-auth ingress protection is separately required.

An operator-only false-positive recovery candidate clears only the specified actor counter and appends the reason and command ID to private audit history. A repeated command returns its original result and cannot clear a newer window; changing the actor or reason with the same ID is rejected. It does not modify identity, sessions, passwords or enrollment HOLDs. This is not a complete recovery service: authenticated administrator approval, user-facing workflow, audit export/retention and independently tested production restoration still need implementation.
