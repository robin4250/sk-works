# Bootstrap-connected logout persistence fence

The pinned SupabaseFlutter 2.17.2 AuthState listener starts persistence unawaited and catches/logs storage errors. SDK signOut completion therefore does not acknowledge removal of the persisted session. The actual SupabaseBackend bootstrap now supplies a LocalStorage wrapper and binds its credential-free fence port to the repository gateway before publishing initialized state. Other Auth options retain their existing defaults.

The original `sb-<project host prefix>-auth-token` key, SDK session serialization and unrelated preferences are retained. A separate project-namespaced marker contains only canonical `pending-v1`, never credentials or decoded user IDs. Before SDK restoration, wrapper.initialize reads that marker. Missing marker permits ordinary restoration; pending, unknown, wrong typed or unreadable marker blocks hasAccessToken/accessToken and initializes navigation quarantine as failed. Uninitialized storage is also closed. Existing stored session content is not migrated, copied or exposed by the fence port.

Logout intent synchronously closes memory/storage admission. The production session adapter observes platform set/remove booleans and reloads preferences before readback; cache eviction alone is not deletion proof. Marker release is followed by another fresh session-absence read. A serialized queue drains an already-started save before acknowledging the marker. Queued older-generation saves and saves admitted during quarantine cannot resurrect a session. The marker must write/read back successfully before SDK logout or token removal. If marker acknowledgment fails, the original stored token is preserved and the in-memory UI/write fence stays closed; restart protection cannot be claimed without a successful persistent marker. A subsequent explicit retry is required.

After fresh SDK null-session signedOut and currentSession null, the gateway explicitly removes the stored session and checks both hasAccessToken and accessToken readback. It retains the AuthState observer while marker release executes and rechecks proof before/after asynchronous removal and after observer cancellation. Marker clear/readback failure or proof drift retains/rearms the marker and keeps UI closed. No old token is restored or resent, and no password/provider request is retried. A failed medium may prevent marker rearm; this remains an unknown persistence outcome, never a successful release.

All SDK session persistence events, including OAuth/refresh events handled by the pinned SupabaseAuth listener, pass through this configured wrapper. SDK in-memory writes, OAuth/deep-link/recovery mutation ownership and PKCE verifier storage are not claimed as owned by this gateway. Direct out-of-band SharedPreferences writes, another isolate/process, device backup/restore and OS/power-loss durability remain outside its proof. SharedPreferences acknowledgment/readback and simulated restart tests are not physical iPhone durability evidence. Server revocation and real-device delivery remain separate. Apple adoption and individual document exemption remain OFF; no production/provider/DB/key/deployment changes.

Validation pending scoped CI: marker absent/pending/malformed/read/init failure, marker ACK failure preserving original, in-flight/late saves, deletion/readback/clear failure, proof drift, exact SDK key and unrelated preference preservation, and actual SupabaseFlutter initialization/session callbacks with ordinary and fenced startup. Existing quarantine and gateway tests remain included; no passed TLS suite is manually repeated.
