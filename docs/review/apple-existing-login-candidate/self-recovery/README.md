# Apple self-recovery orchestration — isolated, OFF

The existing recovery function remains restricted to a root operator. This candidate demonstrates the required caller-side checks before an owner may request reconciliation: exact verified original session, request ownership and held status, fresh primary-password verification that closes its temporary session, and a server-generated command bound to actor, original session and request. It returns a generic review state unless the trusted reconciliation confirms completion or cancellation. Cancellation requires a newly authenticated Apple credential; it never permits replay of the old token.

This is not a usable recovery endpoint. `readOwnRequest` and `reconcileOwnHeld` are trusted ports, not implementations; the latter must enforce ownership again in the same transaction and use the existing audited root function safely. The real proof issuance, durable idempotent recovery after an unknown response, rate limiting, least-privilege operator boundary, user interface, real GoTrue, on-device verification and production safety/rollback are absent. Do not supply true gates or connect privileged ports until these are implemented and reviewed. No production Auth, roles, grants, sessions or identities are changed.
