# New-session reply recovery — review only, OFF

The ordinary ready-job, canonical registration, delivery and consent functions
continue to reject a different SID. No old claims, job, original PDF or consent
are overwritten. A fixed private recovery route requires the same original
actor, current exact company membership, live SID, feature ON, saved site and
recipient registry, current approved revision, identical body/render hashes and
the still-current registered issuer seal. Changed seals, links, roles, revisions
or feature state cannot be repaired merely by obtaining a new lease.

A read-only preview fixes the original acceptance evidence and its three hashes.
Explicit affirmative confirmation creates an append-only lease for that current
SID. Only two generated private copies use the extra lease; the original function
bodies and catalogs are unchanged. The registration copy differs at the exact
old-session predicate and adds a final lease recheck; all existing evidence,
recipient, revision and immutable-byte checks remain. Delivery uses the same
original job and original recipient, with current recovery evidence rechecked.
There is no public caller-supplied PDF upload or request-supplied SQL/recipient.

The fixed coordinator locks the original job first, reads existing bytes in a
fresh statement, and renders only saved evidence when no PDF is registered.
An existing original is reused byte-for-byte. Every stage installs only current
cryptographically verified claims LOCAL in a dedicated transaction. A lost
COMMIT response is UNKNOWN and never causes an automatic rollback or resend.

The confirmation/reconciliation lock uses the canonical preview, actor and
company. A separate delivery lock waits for storage to finish. The append-only
cancellation barrier denies late confirmations or late workers after a proven
cancelled result; a negative status snapshot is not a cancellation proof.
Results may be inspected with the normal archive-read actor while the feature
is OFF. UI/persistent reply journal integration is not included in this first
source connection and remains unfinished.

## Evidence and limits

Local PGlite composition passed 288 package checks at the pre-publication
barrier version, including actual Dart PDF generation and unchanged complete
original-function metadata, job and consent values. Twenty Node coordinator
tests passed, including all three lost-COMMIT stages. The final added ordinary
old-SID registration denial must be checked by the latest published head's CI;
earlier success is not transferred to it.

The canonical fixture uses explicit synthetic surrounding authorization and
other review-only consent/API dependencies. It is not the deployed production
contract and does not prove real GoTrue, live company data, hosted Edge limits,
native concurrency, full production catalog guards or a safe rollout. This is
not a production migration. Actual dependency reconciliation and a guarded
combined installation remain prerequisites; no existing deployed helper may be
silently replaced with a fixture helper. Production HOLD and initial OFF remain.
