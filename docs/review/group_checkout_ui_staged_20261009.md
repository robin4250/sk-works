# 現場メンバー退勤UI：段階導入

本人の既存退勤（GPS・写真を含む）を先に保存する。保存済みの元出勤ID・勤務日を維持し、その後だけ現場メンバーの代理退勤を案内する。入力者の位置・写真を他メンバーへコピーしない。

サーバー `get_attendance_rollout_capabilities(p_company_id)` の version=1・本人の会社ID一致・group_checkout_enabled=true が揃った場合のみ候補RPCを呼ぶ。会社IDは既存本人RLSで読める出勤anchorから取得する。機能OFF・migration未適用・能力不明・通信例外なら既存の本人退勤→日報を維持する。

機能ON時は同現場・元勤務日の候補を自動表示し、未退勤メンバーだけを初期選択する。退勤済み・早退は選択不可、既存時刻を保持する。選択対象だけを専用RPCへ送信する。送信中は操作を止める。通信結果不明時は対象を固定し同じUUIDリクエストで再試行する。本人の退勤INSERTをやり直さない。日報へ進む場合は他メンバーの未処理/結果未確認を明示して確認する。

候補勤務日が違う、同一人の勤務候補が重複する、日付/退勤時刻が不正なら拒否する。確認画面の退出から既存日報画面へ進み、元の現場・勤務日を渡す。通知はこの画面で発行しない。

未完成：サーバー能力RPC・group migration本番適用/ON、日報登録後の確認通知、日本語/英語の最終辞書・既存「？」ヘルプ統合、実機通し確認。ローカルFlutter SDKがないため追加4純粋テスト＋1WidgetテストはCI待ち。勤務方式や未登録写真/GPSの扱いはこの変更で勝手に変更しない。

実連動追加：元出勤IDを車両メーターと現場日報へ引き継ぐ。日報はON時に実候補source IDをメンバーへ付与し、既存の時間・手当・距離入力を保持しながら不足する実出勤メンバーをdraftへ追加する。signed日報へ無承認で追加しない。保存直前に候補source IDを再検証する。既存の証跡link RPCは写真あり限定のため、保存成功後に専用attach_group_report_sources RPCを呼び、写真なしproxyも明示source IDsで結合する。返却report ID/source IDsを厳密に照合し、不明時は同じ日報の再保存へ誘導する。未退勤メンバーは下書きへ残し、確定署名前は退勤確認を要求する。専用SQL migration本番適用/ONは未実施。

車両ON連動追加：能力が明示ONの時は旧車両保存RPCを呼ばず、日報保存後の限定read-only contextから実運転手のclaim/eventを確認し、保存済みメーターeventだけを専用RPCで日報へ結合する。元source・event・前回/今回/当日距離のsnapshotを読み込み、画面/PDFへ同じ値を表示する。他の運転手のメーターは編集不可。未登録は下書き保存可能だが署名前に止める。旧データや未知能力を推測修復しない。車両OFFは旧保存方式を維持する。admin非参加者による既存承認修正とスナップショット保持はON前の追加検証対象。
