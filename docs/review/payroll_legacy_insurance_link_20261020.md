# 旧保険料の保存済み内訳から固定表示枠への接続を復旧

基準main c8216d9a31e0d8340c9ec123307907bc148191a8。ユーザーは固定表示枠の追加後に保険料が見えなくなった可能性を報告し、残っている所得税と住民税を維持するよう指示している。一般の手入力モードを新設して代用する変更ではない。

固定枠追加commit03e5823eのdiffでは旧所得税/社会保険月額入力をPayrollFixedDeductionsへ置換した。一方、既存custom_deductionsを固定名で捨てる変更は無く、保存時も残す。原本settings保存・税/保険計算・合計・PDFは今回変更しない。

既存apply_payroll_custom_moneyは、旧named保険料を保存済みdetail.custom_deductionsへ保持する。自動税条件が無いとtop-levelのnamed保険キーは存在しないことがある。固定枠がtop-levelだけを見るため、保存済みの正しい保険額があっても空欄になる。PDFは既に保存済み配列を描画するため、この経路では金額消失と固定枠表示欠落を区別する。

本変更は自動税条件も計算結果も無い、未保留の同月明細に限り、top-levelのnamed額が存在しない場合に保存済みcustom_deductionsの同一正式名称から読取表示する。明示top-level0は維持、不正/負額/超過額は採用しない。旧社会保険合計から健康・年金・雇用・介護を推測配分しない。自動計算条件を登録済みの場合の参照を変更せず、旧額を自動計算結果と誤表示しない。旧明細の表示は読取専用。

検証候補は、元mainと同じ新テストで保存配列の健康保険料が空になるREDを要求した後、修復済み固定枠・個別設定の全関連テストを実行する。所得税・住民税・会社共通手当の保存済みsnapshot不変、手当1項目だけ編集保存したときの既存保険/月額税/既存formula維持も検査する。手元にFlutter SDKが無いため実Flutter成功はCI結果待ち。

限定実データ照会では既存保護明細のhash一致を確認したが、当該原本から以前の正額保険設定はまだ特定できていない。他の従業員・以前の表示・削除前値の可能性を否定しない。本変更だけで実際に消えた保険額を復元した、本番給与が直った、アプリ配布済みとはしない。実ID/実額/私有原本はこの文書へ記載しない。
