# Canonical common payroll resolver connection

Review-only, no production operation. This unit depends on the canonical snapshot preparation unit and the existing bridge/effective canonical implementation. It does not install or consume a second future-policy or legacy-publication table as a permanent payroll route.

The existing `payroll_publications.items` is the sole effective publication source. Ordinary month/day/hour items retain the original resolver branch and output shape. An explicitly approved `origin=company_legacy` snapshot item uses `attendance_selected_distinct_dates`, including selected zero-man-day dates and deduplicating same-day attendance. Unselected working dates do not pay it. IDs, generations, display units and publication metadata are carried into rows with `origin=company_common` and `source_origin=company_legacy`, preserving the existing frozen common-card reader.

The shared augmenter uses a narrowly derived fresh worker-settings overlay to suppress a same-name/same-rate old individual slot in calculation only. Original settings are never updated. Absent slots inherit; different individual amounts, ambiguous names, custom/unit overlap and unknown historical selections remain unresolved rather than being silently reassigned. Explicit per-worker different-rate preferences are not yet part of this canonical contract. The five normal refresh/tax/attendance callers remain unchanged and no new salary-view requirement is added inside trusted calculation. The helper is revoked from every application role.

Exact source plus owner/ACL/configuration/security/return-type/argument and schema guards protect the two replaced functions. The review SQL has no activation, publication, financial DML, new public endpoint or role grant. Installation is not deployment-ready: normal publisher preview, explicit first activation, approved contract persistence, receipt/readback and UI still need versioned integration. Existing old public publish does not accept the extended legacy contract; the fixture inserts an approved canonical publication as owner in its disposable database, not through a production-ready endpoint.

## Isolated evidence

`tool/verify_company_common_canonical_resolver.mjs` uses the public canonical baseline and supports the existing PGlite/loopback PG17 adapters. Synthetic and private-rate PGlite inputs passed actual attendance-trigger salary creation, selection edit remove/restore, same-day dedup, selected zero-man-day, ordinary day/month quantities unchanged, a new employee, same-rate overlay without writes, conflict/unknown-name refusal, manual preservation, frozen-card compatibility, unchanged caller hashes/metadata and five invalid prerequisite mutations. Identical duplicated snapshot items are rejected. No alternative future-policy schema is installed.

Private-rate inputs stay outside git, use synthetic account IDs and are not copied into this unit. Native PG17, real issued JWT/RLS/proxy authorization, concurrent changes, normal publisher execution, payroll screen/PDF/print/share and administrator iPhone remain unverified. The no-salary-view test runs trusted triggers as fixture owner with actor claims; it is not an authenticated proxy endpoint proof.
