# 現在の会社共通手当と給与用履歴の表示分離（2026-10-25）

## 実機の問題

会社共通設定の日単位・支給は全削除済みなのに、他社員の個別給与設定にPC2500／鉄骨2500が「社内共通手当」として出る。齊藤竜一は同月で適用前の空表示。社員の削除・再作成で回避しない。

main e5d53daba0dcf9abc66377895f37698bd5676a0d と本番catalogのsourceを確認した。今回の変更は表示と入力状態の区別のみで、金額・給与条件・署名・receipt・本番データを書き換えない。

## 原因

payroll_unit_private.common_state(uuid,uuid,date)（MD5 ee332d5b1ee6f02a8432b7194a36dfab）が返すcompanyCommonItemsは、社員の給与形態・適用月・publication・過去の確認済み価格receiptを解決した**給与用の条件**である。現在会社に登録されている項目一覧とは別。

従来pageはこの給与用条件をそのまま「社内共通手当」「会社の設定を給与へ自動反映」と表示した。そのため、会社の現登録は空でも、社員ごとに異なる給与履歴が現在登録のように見えていた。

current登録名は別の既存readerから取得し、個別pageがworker.pay_typeまたはlegacy allに絞って渡している。給与形態が異なる社員まで、同じ登録群へ強制統一しない。

## 修正

- registeredAllowanceNamesLoadedを追加。取得成功0件と未取得／取得失敗を区別する。
- 個別page側にはLoaded接続と、既存の会社共通設定入口へ開くcallback、個別月額行の由来ラベルを最小追加する。保険設定UIと競合する場合はrootが別保存の個別patchを適用。共通設定から戻った際は登録名だけを再読取し、未保存の個別／単位別draftを消すreloadは呼ばない。
- 現在月以降の未確定設定に「現在の会社共通手当」を、会社の登録名から表示。0件ならこの区分は未登録と表示する。時間・日・月の全区分で同じ欄を保持し、給与snapshotがない場合も月欄をOffstageにしない。未取得・取得失敗でも欄は残し、確認中／確認不可を表示する。
- 同条件の社員は、給与用の旧履歴が異なっても同じcurrent登録名を見る。新しい登録名も個別保存をせず表示される。
- 給与用条件が現在登録のID・名称・section・unitと一致する場合は「この月の給与用手当」に分離。既存の時間数編集を維持。
- 現在登録から削除・改名された給与用条件は、「登録変更前の給与用手当」へ分離し初期状態で折りたたむ。原本や額を消さず、展開すれば確認できる。旧時間条件の編集はread-onlyとする。
- まだこの月の給与計算用に残っていることと、会社の登録変更だけでは給与用記録は更新されないことを明記する。
- 過去月／frozen給与では最新登録で置換せず、元の給与用条件を保持。
- 取得失敗・未取得を空登録扱いしない。history_missingによる計算保留も維持。
- 無条件「給与へ自動反映」という文言を「この月の給与計算に使う条件」へ修正し、？ヘルプも更新。

current名readerは価格を返さないため、最新単価を推測したり過去の給与単価を現在登録の単価として表示しない。現在登録カードは名称のみ。最新の単価は会社共通の登録画面が原本。

## 保存・金融境界

保存RPC、月別時間数のpayload、給与計算・保険税計算、確定検証は変更しない。現在表示を統一したことは「全員の旧金融設定を削除した」「今月の給与へ新設定の実額が適用された」という意味ではない。後者は既存の適用条件・正規再計算／承認で別途確認する。

この修正は個別delete、全員0円、偽の未登録、社員削除を使っていない。現登録が空でも、実際の過去確認済み手当を給与明細から隠さない。

## 検証

新widget回帰を20ケース追加。

- 現登録0・旧PC/鉄骨の給与履歴ありで、currentは空／旧履歴はfolded保存。
- 社員間の給与履歴差があっても同じ新current登録名。
- 未取得・失敗を0件扱いしない。
- frozen／過去月は元の記録。
- 同IDの改名で古いsnapshotを書き換えない。
- currentに一致するhourの編集維持、退役hourはreadonly。
- 計算履歴欠落でも登録名は表示し、給与保留を維持。
- 読取表示による保存呼出し0、元の額不変。

ローカルFlutterは実行しない。remote Flutter解析・上記widgetと既存関連回帰の成功待ち。実機・実給与の反映確認は別工程。

## 追加の由来表示と編集先

会社共通は現在登録の見出しと事業所アイコン、個別は「個別手当（この社員だけ）」で区別する。旧月額個別行にも同じラベルを付ける。会社共通は既存CompanyCommonAllowanceEntryPage（会社scopeとサーバー権限を再確認）へ開き、個別は既存editorで編集する。同名の共通・個別でもIDを混ぜず、current登録名をpayableな個別items配列へコピーしない。給与用の旧snapshotは別の履歴見出しで保持する。

時間区分では、退勤の実勤務時間との連動が準備中で、登録名の表示だけでは給与へ反映しないことを明示する。月別時間数の既存入力と、まだ未接続の退勤実勤務時間を混同しない。

旧legacy slotと会社legacy IDが対応する場合の既存二重表示除外を、現登録／旧給与用の両projectionで維持する。同名だけで除外せず、違うslot／IDの独立項目は保持する回帰を追加した。
