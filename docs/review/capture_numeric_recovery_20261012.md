# GPS＋写真の保留再確認で数値表示差を照合

2026-10-12の実機写真で「保留中の勤怠記録が一致しません」を確認。本番のread-only SELECTでextra_float_digits=0と15桁のfloat8 JSON表現を確認。元の35.703883354849315が35.7038833548493、139.81095488528197が139.810954885282となり、従来のDart完全数値比較では同じ撮影でも拒否する。

latitude・longitude・accuracy_m・distance_to_site_mの数値だけを有限値と15有効桁のDB表現で照合する。任意の距離・時刻許容幅は追加しない。ID・会社・本人・現場・ルート・写真・状態・時刻は従来の一致条件を保持。元のpayload、写真、server snapshotを変更せず、履歴化済みの場合は既存の明示的な「新しい出勤を始める」で端末履歴へ保持してから保留を解除する。DB設定、既存記録、tombstoneは変更しない。

回帰テスト：15桁の4数値を返す再確認でINSERTなし、実際に違う数値/本人/写真/ID/契約版/文字列数値/non-finite/nullは拒否。実HTTPで丸められたarchive応答、写真不一致時の保留保持、通信失敗時の保留保持、明示的承認後の元payloadと写真参照の保持を確認する。実機のRelease確認は別途必要。
