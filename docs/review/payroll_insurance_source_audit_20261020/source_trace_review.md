# 保険料の旧自動連動: 参照先・保存履歴の限定追跡

2026-10-20。最新ユーザー報告は、固定表示枠を増やした頃から保険料が見えなくなり、現在残っている所得税と住民税を壊さず復旧してほしい、という内容。手入力新機能で代用する作業は保留している。

## ソース経路

固定枠追加03e5823eの親2054f698にある個別設定画面も、旧social_insurance_monthly・custom_deductionsを読む方式で、独自の保険料率計算やpersonnel/資格書類からの算定は無い。追加時のdiffは旧所得税/社会保険入力と税条件ボタンをPayrollFixedDeductionsへ置換した。既存custom配列を保険名で捨てる変更は確認されない。

自動税計算の最初のmigration20261010030208から、保険計算はworker_conditionsを有効月で参照し、無ければnullを返す。後続のunit/override拡張でもこの入口は維持され、personnel資料からの推測経路へは移行していない。設定保存のsocial値保持は既存一般saveに残り、今回PR1297で別手当だけを保存した際の所得税・住民税・保険保存額保持を追加した。

確認できた固定枠のregressionは、既存hookがnamed保険を保存済みdetail.custom_deductionsへ格納するのに、固定枠がtop-levelしか見なかったこと。この経路は元sourceのREDと修正版GREENを親がCIで確認済み。ただし対象の過去正額全復元とは別の完了状態とする。

## 限定本番SELECT

実値や個人IDを出力せず、件数/型/存在/一致だけを照会した。会社保険料率5種・会社scope・料率更新履歴は残っている。個別tax条件とその変更履歴は対象・会社とも0、unit条件4件は全items空。保護済み対象給与は原本hashと一致し、現控除合計は保存済み所得税+住民税に一致する。社会保険額が合計内だけに残る状態はこの対象では確認されない。

workers/personnel_profilesには加入条件・保険額・標準報酬を保存する列/JSON profileが見当たらず、personnel変更申請でも保険関連構造は見つからなかった。一般給与設定にbefore/afterを持つ専用履歴はなく、payroll_auditにはaction/revisionだけがある。generic master audit内の給与設定候補、確定給与履歴、保険名の給与調整（取消含む）にも今回scopeで復元材料は無かった。資格書類・住所・家族情報の実内容は推測材料として読んでいない。

## 限界と保持

これらは現在の限定保存先の観測であり、以前の正しい表示や別従業員・別月・以前のpreview・別の私有バックアップが存在しない証明ではない。0や履歴なしを保険未加入とは解釈しない。料率employee/employerは割合であり、本人の月額や算定基礎ではない。正額が発見されるまでは架空の額/加入flag/標準報酬を保存せず、会社料率と既存所得税・住民税をそのまま保護する。

本調査はSELECTのみ。本番再計算、DDL/DML、Auth変更、保険料の一律登録、設定の自動作成は行っていない。実保険の全連動と正額復元は未完了として引き継ぐ。
