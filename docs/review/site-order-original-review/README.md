# Persisted original review and explicit sharing UI — source Draft

This continuation exposes only existing canonical PDF bytes under exact purpose
identity and current company/actor/role authorization. Metadata uses immutable
approved issuer/body/seal snapshots; OFF or a new live SID permits read-only
inspection. Bytes are bounded, PDF-header checked and SHA/length matched on both
server and client. No read renders, registers, consents or sends.

Fresh compose flow can open a separate original-review page after a consent job
is observed. Original registration is explicit; sharing requires displayed
verified bytes, original-session permission, row prices/units/quantities, a
checkbox and a second recipient/terms confirmation. Unknown writes retain local
quarantine and become status-only. Current server approval/context/seal fences
remain authoritative. Recipient inbox storage is labelled separately from the
recipient's unobserved approval. Company/session retirement and lifecycle hiding
mask the PDF, body and an open confirmation dialog.

Early source candidate. Widget tests, actual Native reader/SDK composition and
latest CI are not yet verified. Recovery-list entrance, verified terminal local
journal clearing and new revision/reconsent editing remain unfinished. There is
no production change, real invitation/send, feature enablement or iPhone proof.
