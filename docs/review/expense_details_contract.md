# 経費申請・4一覧・帳票詳細の独立準備

未接続のsource foundation。ホーム導線、実DB保存、申請送信、承認者設定、給与・請求・支払の金額計算、既存PDF生成元は変更しない。

- 振り分け用は全従業員の全申請。未分類だけに絞らない。自社／下請け・協力会社／取引先は分類別。全区分で承認済・未承認・却下を保持する。
- 全一覧から申請者IDを指定した個人一覧へ進む。氏名一致で本人を推測しない。
- 初回承認で自社へ。以後の振り分けは同じexpenseIDのまま。重複承認は現在の分類を勝手に戻さない。却下履歴の分類を消さない。
- 本人給与明細は分類によらず本人の申請全件（未承認／却下含む）。未送信draftは別型であり申請一覧・帳票へ渡せない。下請分は相手ID一致の支払証明書、取引先分は相手ID一致の請求書にも詳細表示する。
- 精算候補（承認済）と表示履歴を分ける。却下は候補にしない。精算期・支払済・確定snapshotは未定のため、承認済をそのまま金額へ足す実装はしない。JPY金額へ税率等を新規適用しない。
- 会社scope不一致は拒否。同一IDの完全同一データは一件にし、異なる版・状態・金額が競合する場合は推測採用せず拒否する。
- UIは外部から権限検証済callbackと保存済一覧を受け取る。callbackなしは変更不可。callback成功だけでローカル表示を承認済にせず、親からの更新データを待つ。個人ページは閲覧専用。実申請入力・永続化・送信は未実装。
- PDF rendererは呼出側documentとfontを受け取り詳細だけ追加。対象0件なら追加しない。合成1頁の次へ追加して検証する。既存給与15項目／請求35明細ごとの続頁は削除せず、実統合時に「既存1頁→経費詳細→既存続頁」の順を検証する必要がある。
- fixtureのPDFは全て合成データ。既存帳票への組込み、本番資料・実データ・過去確定帳票の更新を証明しない。

未決事項：申請を承認できる担当者、対象期間と過去申請の扱い、確定時の保存詳細snapshot、保存・承認RPCと権限、申請金額を各帳票本体へ採用する契約。Work側のDB／給与レーンと調整してから接続する。

## 2026-10-10 個人申請・経費専用承認の接続中

既存の未保存コードを引き継ぎ、利用日カレンダー・金額/内容・本人所属・利用月別履歴・固定UUID再確認の個人申請画面と保存RPCを実装した。申請前に端末へ同じ内容を保存し、照会失敗を新規送信へ置き換えない。申請者が変わった場合は前の情報を表示せず、却下済み申請も履歴に残す。14件の関連Flutterテストと静的解析が成功。画面のホーム導線はまだ未接続。

専用 `expense_approval_settings` は既存の承認担当を初期値として取り込み、その後の変更は他ページに波及させない。既存の勤怠修正承認と同じく、選任担当だけが決定し、担当が複数の場合は申請者本人の承認を許さない（担当1名の既存例外は維持）。設定変更は会社のowner/admin、候補はowner/admin/manager/viewerに限定。全件一覧を読めるのはowner/adminまたは経費の選任担当。

承認で初めて自社へ、既に承認済みの重複承認は振り分けを戻さない。振り分けは承認済みに限り、自社・同社customer・同社partnerのIDで保存。却下でも過去の分類を保持する。各操作に固定command UUIDとrevisionを持たせ、通信再送は同じ結果、別の更新との競合は再読み込みとする。原申請金額等は更新せず、操作結果の履歴を別保存する。隔離DBで本人範囲・月・再送・承認/却下・他社振分け拒否・担当変更の分離を検証済み。

本番未適用。残る接続は管理一覧/担当設定のRepositoryと画面、ホーム導線、既存3帳票の明細と確定時snapshot、CIと実機確認。既存給与・請求・支払の金額や過去確定帳票は変更していない。

## 2026-10-10 管理画面と帳票生成への接続

ホームの「経費」から本人申請と全員一覧へ進める。全員一覧は会社・利用月・4分類、本人別閲覧、承認・却下・自社/取引先/下請け振分け、経費専用担当1〜3名の設定を接続した。固定操作UUIDを送信前に端末へ保存し、応答が不明な間は別操作を止め、同じ操作だけ再確認する。会社・アカウント切替と更新版の競合を検証する。

3つの実PDF生成器に経費詳細を接続。給与は本人の全申請、請求書と支払証明書は割当先ID一致の申請を利用月で抽出し、1ページ目の直後へ追加する。給与既存の続ページもその後へ保持。請求書モデルのcustomerIdは名称のため対象照合には使わず、保存済みinvoice IDからDB側のcustomer UUIDを決定する。現時点の金額加算は行わず、元の給与/請求/支払の合計を保持する。

新規の帳票確定時のみ、経費明細を専用の非公開snapshotへ同一トランザクションで保存。確定後の再振分けや却下は過去のsnapshotへ反映しない。導入前の確定・legacy帳票に経費明細を追補するバックフィルはない。未確定は最新明細を読み、帳票の版・月と利用者が一致しない取得結果では出力を止める。実DBに帳票IDがないローカルpreviewや協定書snapshotには明細を推測追加しない。通信失敗時に「経費なし」として出力を進めない。
