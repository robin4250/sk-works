# 経費申請・4一覧・帳票詳細の独立準備

未接続のsource foundation。ホーム導線、実DB保存、申請送信、承認者設定、給与・請求・支払の金額計算、既存PDF生成元は変更しない。

- 振り分け用は全従業員の全申請。未分類だけに絞らない。自社／下請け・協力会社／取引先は分類別。全区分で承認済・未承認・却下を保持する。
- 全一覧から申請者IDを指定した個人一覧へ進む。氏名一致で本人を推測しない。
- 初回承認で自社へ。以後の振り分けは同じexpenseIDのまま。重複承認は現在の分類を勝手に戻さない。却下履歴の分類を消さない。
- 本人給与明細は分類によらず本人の申請全件（未承認／却下含む）。未送信draftは別型であり申請一覧・帳票へ渡せない。下請分は相手ID一致の支払証明書、取引先分は相手ID一致の請求書にも詳細表示する。
- 精算候補（承認済）と表示履歴を分ける。却下は候補にしない。精算期・支払済・確定snapshotは未定のため、承認済をそのまま金額へ足す実装はしない。JPY金額へ税率等を新規適用しない。
- 会社scope不一致は拒否。同一IDの完全同一データは一件にし、異なる版・状態・金額が競合する場合は推測採用せず拒否する。
- UIは外部から権限検証済callbackと保存済一覧を受け取る。callbackなしは変更不可。callback成功だけでローカル表示を承認済にせず、親からの更新データを待つ。個人ページは閲覧専用。実申請入力・永続化・送信は未実装。
- PDF rendererは呼出側documentとfontを受け取り詳細だけ追加。対象0件なら追加しない。合成1頁の次へ追加して検証する。既存給与15項目／請求35明細ごとの続頁は削除せず、実統合時に「既存1頁→経費詳細→既存続頁」の順を検証する必要がある。
- fixtureのPDFは全て合成データ。既存帳票への組込み、本番資料・実データ・過去確定帳票の更新を証明しない。

未決事項：申請を承認できる担当者、対象期間と過去申請の扱い、確定時の保存詳細snapshot、保存・承認RPCと権限、申請金額を各帳票本体へ採用する契約。Work側のDB／給与レーンと調整してから接続する。
