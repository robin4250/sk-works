# Atomic C → terms → typed form V1 → form V2 review

Production HOLD remains. This is an offline review generator and disposable
fixture, not an installer, migration, activation or authority to send documents.
No production catalog capture, OID, complete live definition or business row is
committed here. The generator reads explicit private captures supplied by the
operator, verifies the four existing source SHA256 values, and writes a private
review bundle. It has no database or network client.

The generated forward contains one transaction, with the original four pinned
segments' outer transaction wrappers removed mechanically. Before any change it
compares every `pg_proc` field (including the source body) for ten captured
functions, complete master `pg_class`, and every original constraint. Shared
profile captures must match each other. The original component guards remain.
Afterwards thirteen affected functions' complete attributes are compared with
the disposable expected catalog, resolving cluster-local owner/language/schema
OIDs. Existing source/profile/master-public OIDs remain; the original saver OID
must remain under `before_confirmed_terms`. Five unrelated authorization
functions remain fully exact. The master table remains exact, other constraints
remain exact, and only the named CHECK changes to its exact additive expression.
Raw CHECK parser-location offsets are not portable and are checked through the
exact deparsed expression plus every other constraint attribute. The new flag
must remain absent/OFF; no flag row or business record is written by installation.

The new atomic wrapper needs validation beyond previous component success. The
CI first reuses the existing ordered 49 assertions unchanged to capture only a
**disposable** expected catalog. A second fresh disposable fixture generates the
same bundle from its own before-capture, forces a postflight failure after all
four segments, and verifies the complete rollback. It then executes the correct
bundle, compares every synthetic business table's rows, checks schema-2 access,
master-OFF denial, repeated-apply refusal, and restoration eligibility.
Native PostgreSQL 17.6 and PGlite run the same SQL. Native reset is restricted to
an explicit loopback fixture database/password and a marker established while
the database is empty. No arbitrary database URL or production reset is accepted.

After COMMIT, restore is separately reviewed and requires stopped writers,
completed in-flight calls, an exact committed catalog receipt and no later
source/dependency change. Feature OFF alone is not a writer-stop guarantee. The
eligibility SQL is stricter than schema2-only: **any** saved terms/form-fields
receipt refuses restoring the legacy saver, because that would remove existing
immutability/validation protections. Repair forward in that case.

A source-only restoration retains all additive delegates/functions/CHECK/OFF
rows and every original document. The current saver keeps its newly allocated
OID; the original saver remains in its private delegate. Do not claim a full
identity rollback, uninstall, data undo or permission to DROP anything.
The fixture's operator declaration exercises a check; it does not prove a real
maintenance window, live GoTrue session, installed iPhone or native printer.
