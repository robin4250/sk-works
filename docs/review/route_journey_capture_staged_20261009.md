Base main 6418b3631c7f81f3eb507f8b6c4a7405e8b35326. The older sk-works-journey worktree had only route selection and vehicle/report integration; no intermediate checkpoint persistence. This change does not duplicate its existing route_assignments/ordered route_stops or create fake attendance clock-in/out rows.

New version-1 private rollout defaults OFF. Workspace requires an exact personal route clock-in with original server work_date, location_photo capture v1 and existing capture capability. UI hides capture when capability is absent/OFF; new INSERT also checks server rollout, an open actual shift and an exact existing route stop. The user explicitly selects company departure or direct travel; that saved classification is immutable for the source. It does not assert that a GPS coordinate was the company address.

Existing GpsPhotoCaptureController and metadata service provide actual coordinates/reverse-geocoded address, explicit-zone shutter time or null, separate camera-return observation time, and failure states. Planned stop names/addresses never replace captured address. Saved intermediate failure/photo/GPS/time payloads are immutable. Route stop order/name and original shift/company/worker/date are server snapshots; only validated daily_report_id linking can change.

The client saves an immutable UUID/payload under exact user/company before submitting. The company comes from the exact server source workspace, not an arbitrary first membership. Multiple pending companies are enumerated for explicit source selection. Every retry first reads its own UUID; read failure cannot insert, mismatched/colliding records cannot be joined. Next-calendar-day pending drafts may recover an existing row but cannot create a new row. A lost response never deletes a possibly saved photo. Preference removal occurs only after exact row/payload verification.

New private attendance-route-evidence bucket is independent from legacy attendance orphan cleanup. Its INSERT checks actual personal open source, route, worker, company and OFF capability; source UUID is included in the path. SELECT uses existing own-worker or can_manage_attendance scope, plus existing account-access guard. There is no UPDATE/DELETE policy. Save validates an existing uploaded object and prohibits photo-path reuse across checkpoints. Raw rows and bucket objects are not generally granted to clients.

Daily report links only sources already attached to the exact editable saved route report and roster/original work_date. Reading route evidence follows report membership and existing scoped attendance-photo permission. New evidence uses the same sole PDF generator and byte cache as preview/print/save/share. Storage bucket, original source, selected stop, address, shutter/observation times and bytes affect the PDF fingerprint; signed URL widget keys include bucket/path. Existing evidence retains attendance-evidence as its default bucket.
