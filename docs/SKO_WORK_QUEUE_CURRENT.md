# SKO Work Queue

このファイルは、チャットが切れたり再開した時に「今どこまで終わっていて、次に何をやるか」をすぐ確認するための作業継続メモです。

# 最優先・毎回最初に確認

## Apple Developer Program 承認状況

- SKO作業を再開したら、まず最初に以下を開く。
- Apple Developer Account: https://developer.apple.com/account/
- 会社登録が `保留中` なら、そのまま次のSKO開発作業へ進む。
- `Continue Your Enrollment` / 登録継続 / 承認済み等が表示されたら、通常開発より優先してApple Developer Program登録完了作業を進める。
- 承認後は、必要に応じて契約同意・メンバーシップ購入・支払い・Account Holder確認まで進める。
- メールを見逃していても、Apple Developer Account画面の状態確認を優先する。
- TestFlight実行前には、この項目が未完了のままになっていないことを必ず確認する。

## 運用ルール

- 作業を始める前に必ずこのファイルを確認する。
- 上から順に優先して進める。明確な理由がない限り順番を飛ばさない。
- 完了したら `完了` に移す。
- 途中なら `進行中` に現在地点・ブランチ・コミット・残作業を記録する。
- 新しい仕様は、実施時期を `今すぐ / TestFlight前 / TestFlight後 / 正式公開直前 / 公開後` のどこかに分類する。
- チャットで決まった重要仕様は、実装前でもここに残す。
- チャット再開時に「SKOアプリの続きをお願いします」と言われたら、まずこのファイルを読み、最上段のApple Developer Program状態を確認したうえで、進行中の次の未完了作業から再開する。

## 1-3. 出勤表カレンダー表示改善

- 週間・月間の両方。
- 土曜日: 青。
- 日曜日: 赤。
- 祝日: 赤。

## 1-4. チャット画面整理

- 普段は名前中心でシンプル表示。
- グループ名タップで会社/所属など詳細表示。
- メンバー一覧は縦並び。
- 最近話した人を上、まだ話していない人を下に整理。

## 1-5. 協力会社ページの集約窓口

連携確定した下位会社を協力会社一覧へ表示し、会社ごとに既存データを集約して見せる。

例: `協力会社一覧 → A社`

A社内の入口:
- 人員
- 資格
- 書類
- 請求書
- 取引設定

### 人員

- A社の従業員一覧を表示。
- 「全員まとめて送る」では、人員基本情報 + 各人の資格 + 各人の書類を全員分まとめて取引会社へ送る。
- A君をタップするとA君の詳細へ。
- A君詳細からA君の基本情報、資格一覧、書類一覧を確認。
- A君だけの情報一式を取引会社へ送ることも可能にする。

### 資格

- A社従業員の資格一覧。
- 資格だけをまとめて取引会社へ送信可能。

### 書類

- A社従業員の必要書類一覧（健康診断等）。
- 書類だけをまとめて取引会社へ送信可能。

### 請求書

- A社から上がってきた請求書を年/月で閲覧。
- 月単位・年単位で絞り込み。

## 1-6. 協力会社ごとの取引設定

A社との取引金額をA社ページ内で設定する。

例:
- 1人工単価
- 残業単価
- 早出単価
- 夜勤単価
- 休日単価
- 手当
- 毎月固定で発生する項目（積立金、管理費、年会費月割り等）

上位会社・下位会社が同じ契約元データを参照し、同じ出勤実績から請求書と支払証明書を生成するため、通常取引分は一致する設計にする。

## 1-7. 請求書 / 支払証明書 / 最終精算

### 通常分

- 下位会社: 出勤実績から請求書を自動生成。
- 上位会社: 同じ出勤実績と契約単価から支払証明書を自動生成。
- 通常分は同一元データなので「マッチング済み / 一致」を表示。

### 臨時の追加・控除項目

請求書・支払証明書の表に手入力できる行を持つ。

例:
- 箱3個 × 1,000円 = +3,000円
- ヘルメット5個 = 控除
- 旅行積立金
- 立替精算
- 特別手当
- その他

入力項目例:
- 項目名
- 数量
- 単価
- 金額
- プラス / マイナス
- 備考

### 差し戻し・承認

- 上位会社・下位会社の双方に「承認」「差し戻し」。
- 差し戻し時は理由コメントを入力可能にする。
- 承認/差し戻し/コメント履歴は保存。
- 未承認項目がある間は精算未確定。

### 最終精算書

双方が最終内容を承認したら、以下を統合して最終精算書を生成。

- 基本取引分
- 下位会社からの追加請求
- 上位会社からの追加/控除
- 双方承認済み項目
- 最終確定額

最終精算書は双方から閲覧可能。確定後の数値は固定し、やり取り履歴は残す。

### 継続項目への昇格

最終精算で承認された追加/控除項目ごとに、

- `今回限り`
- `今後の取引設定に登録`

を選べるようにする。

継続を選んだ項目は翌月以降、請求書と支払証明書に自動反映し、自動マッチング対象にする。

## 1-8. ホームの重要対応表示

通知ベルとは分ける。

- 通知ベル: 「こういうことがありました」という情報通知。
- ホーム最上部の重要表示: ユーザーが対応しないと処理が止まるもの。

今回の精算関連で重要表示に出す例:
- A社から請求書が届き承認待ち
- 差し戻しあり
- 相手側承認待ち
- 最終精算承認待ち
- 未確定精算あり

# 2. TestFlight前に必ずやる

- Apple Developer Programの登録状態を再確認し、承認済みなら登録完了・支払い・必要な契約同意まで済ませる。
- 主要フローの回帰テスト。
- iPhone縦画面・大きい文字・長い会社名/氏名の表示確認。
- 認証、SMS、Face ID、第2パスワードの実機確認準備。
- 勤怠、日報、承認、給与明細、請求書、現場データの権限制御確認。
- Supabase migration / RLS / Storage の最終非破壊監査。
- CIをすべて緑にする。
- TestFlight用ビルド番号・バージョン整理。
- TestFlight配布手順・従業員向け案内PDFの最終準備。
- 実機で確認すべきチェックリストを更新。

# 3. TestFlight後にやる

- 過去修正で発生した給与差額を次回給与へ `過去勤務修正分` として加算する処理。
- TestFlight実機フィードバックの修正。
- 実機でしか見つからないレイアウト・操作・権限・通知・Face ID等の修正。
- 実運用に近い会社間連携の確認と微調整。

# 4. 正式公開直前にやる

- 本番環境の最終バックアップ/再現性確認。
- 本番DB migration適用順とロールバック方針確認。
- RLS / Storage / Auth / Edge Functions の最終セキュリティ監査。
- App Store提出用のアプリ名、説明、スクリーンショット、プライバシー情報、サポート情報を最終確認。
- 利用規約・プライバシーポリシー・問い合わせ導線を最終確認。
- 管理者/サブ管理者/一般ユーザーの説明書とパンフレットを最終版へ更新。
- 初回導入・従業員招待・QR初期ログインの実運用確認。
- 本番リリース候補版で主要業務フローを最終通しテスト。

# 5. 正式公開後にやる

- 公開後にしか得られない実利用データ/問い合わせをもとに改善。
- 操作ログやエラー傾向を見てUI・案内を改善。
- 要望の多い機能を優先順位付けして追加。
- 大きな仕様追加は公開直後の安定化を優先し、安定後に着手。

# 6. 完了済み

完了した作業は今後ここへ移す。PR番号・mainマージコミット・必要なら本番反映状況も記録する。

# 再開時の最短手順

1. このファイルを読む。
2. Apple Developer Account（https://developer.apple.com/account/）を最初に開いて状態確認を依頼する。
3. `保留中` なら `0. 現在地` のブランチと最新コミットをGitHubで確認する。
4. 承認済み/登録継続可能ならApple Developer Program登録完了作業を最優先する。
5. 開発を続ける場合は `1. 今すぐやる` の最初の未完了項目から再開する。
6. 作業完了ごとにこのファイルを更新する。
7. TestFlight前・後・正式公開直前・公開後の区分を勝手に崩さない。

このファイルをSKO開発の作業順序の基準とする。
