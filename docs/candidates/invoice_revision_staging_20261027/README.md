# 請求書訂正案の独立保全候補

本候補は本番未適用・既定OFF・公開GRANTなし。旧請求書の表示、帳票、金額、印影、承認、取引先への公開には変更を加えない。提案の下書きだけをprivate内に保存し、実際の訂正確定・請求送信機能は実装していない。

## 確認済みの制約

- 本番の自動請求は `(company_id, customer_id, billing_period_start) WHERE automatic_calculation` に一意制約がある。同じ月に別の自動請求行を追加できない。
- 現行アプリは `invoices` を直接一覧取得し、承認・注文請書は元のinvoice IDと更新版に結合する。別の手動行を単純追加すると旧版も表示され、二重請求を防げない。
- 旧アプリや既に保存・送信されたPDFを消せない。サーバー/配布先を含む新版識別・旧版の発行防止・既送付分の訂正手順が整うまで実際の新版公開を許可しない。
- 対象には日数以外に手当・残業があり、差額の手入力や目視による推測では復旧できない。計算は別担当の実関数由来previewを使い、取引先・現場単価・勤務・日報・ルート・経費・調整・税・福利厚生の全依存と原本を固定する必要がある。

## この段階での性質

独立schemaに既定OFFの設定とprivateな提案台帳を作る。既存 `can_manage_invoices`、アカウント制限、実session、会社を検証し、membershipと既存permissionをFOR SHARE、元invoiceをFOR UPDATEでロックする。UTCの旧原本SHA256とtrusted previewのsource SHA256を検証する。旧行と全列の原本コピー・提案内容・理由・操作者・セッションをprivateに保存する。旧行への変更、仮の印影・承認の流用、invoiceへの別行追加、公開RPCは一切しない。

表示候補は「訂正案・未発行」を明示し、現場/ルートの保存された行と請求金額を読み取り専用で示す。承認・発行・共有の操作は設けない。画面自体は認証済みread RPCや既存一覧に未接続であり、正式請求書ではない。実データを推測して画面へ注入してはいけない。

同じIDの同一要求は再試行を同じ結果として返し、異なる操作/actor/sessionは拒否。同じ原本の未取消提案は一件だけ。提案作成と原本行へのロックは単一transaction内。提案の内部確認は同じ本人・生きたsession・現在の会社権限を再照合し、原本やpreviewの入力が変わった場合は表示せず拒否する。元行のコピー、session ID、承認や旧印影は確認結果に含めない。新規FKを設けず、既存の請求書・会社の削除可否を変更しない。原本が後から削除された場合は提案台帳に原本のJSONは残るが、関連承認や添付の保全と、削除後の発行拒否を含む完全な復旧は未実装。提案台帳には個人・金額・旧印影情報が含まれ得るため非公開、RLS有効かつclientへのGRANTなし。

## 不足・未配備

- preview側の全入力に対するfingerprintと競合防止、route/手当/残業/税/福利厚生のNative検証。
- 訂正案の取下げ、保存期限、機能OFF時/障害時の復旧、監査閲覧の正式契約。
- 新版の確定・発行は未実装。確定時は再認証と既存会社権限を再確認し、行・全入力の同一transaction照合、競合/再試行/自動再計算と二重請求の防止、新版IDと新規承認を一体で実装する。
- 旧版を保護したまま最新を一意に示す会社/取引先のread API、旧clientからの旧版発行を遮断する安全な互換性、PDF・承認・注文請書・共有先までの整合。
- 原本の実データは一切取得・保存していない。合成環境で既存自動計算の実fixtureと訂正preview PR #1503（head 91804de11c4116021e096c08c226c9f3d5c00314）を使い、現場・ルート・経費・調整・手当・残業を含む実refreshと同じproposal全額、原本不変、source不一致拒否を検証。GoTrueは合成session、Native/二接続のCIは進行中。実GoTrue・本番RLS・実Storage/実機・移行・復旧は未完了。必須バックアップ/実catalog guard後もroot以外は本番変更しない。

独立候補は復旧成功を意味しない。安全な発行経路とユーザーの実機確認が揃うまでは、現行の5日版を旧版として保持し、7日版を発行しない。

追加の失効競合試験は本番catalogから採った認証helper本体と合成Auth/JWTテーブルを使う。BAN・session削除が進行中のprivate reviewトランザクションを待ち、その後の再試行を拒否するかNative 2接続で確認する。実GoTrue試験や、未実装の発行トランザクションに対する検証ではない。
