# 請求書の承認時期：未接続UI候補

対象月が終わってから、対象勤務の退勤・日報確定をサーバーが確認できたときに担当者へ承認ボタンを表示する画面部品。請求書プレビュー画面への接続候補は追加済みだが、サーバーRPCが存在しない間は承認ボタンを常時出さず、確認不可と表示する。従ってこの状態を適用すると正常な請求書も承認できない。現在のアプリには未統合。既存の承認RPC自体や他の承認経路は変更していない。main・本番・配布への適用はしない。

サーバー返却の `invoice_id` と `source_revision` の一致を必要とし、状態 `period_open`、`checkout_pending`、`report_pending`、`ready` を表示する。未知・失敗・未照合・古いrevisionは承認できない。管理者の権限と担当者本人の権限は別判定。ルート、未リンク勤怠、月内の過去の未完了などは端末で推測せず、DB側が全範囲を判断する。`data_changed` は現在未確認として扱う。

サーバーが承認を同一transactionで再判定することが必須。確認後にデータが変わる競合や古いアプリは画面制御では防げない。既存データ・承認履歴・印影の変更は含まない。実サーバー契約、現行画面統合・認可・GoTrue・同時更新・実機確認は未完。

通知経路候補では既存 `invoice_approval` 通知の対象ID・本人/ライフサイクル確認と画面遷移を再利用し、その画面経由でのみ承認ボタンを表示する設計。通常一覧からの表示では「承認は通知から」と案内する。ただし接続候補は現状readyを取得できず通知からも承認不可。既存の通知enqueueは条件適合前に送ることがあり、このUIでは通知時期は保証できない。通知自体の作成や送信、角印確認フローは変更していない。通知経由フラグはUIの経路情報であり、本人や権限を証明するものではない。
