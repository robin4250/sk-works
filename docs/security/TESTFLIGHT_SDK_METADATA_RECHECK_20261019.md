# Existing IPA metadata verification correction

Flutter 3.47.5 adds six framework version fields and two application build fields to DART_DEFINES. The previous verifier accepted only the three explicit application flags and rejected the generated archive after build. The installed SDK's flutter_command.dart `_addFlutterVersionToDartDefines` and build-name/build-number injection, and version.dart's ten-character revision helper, establish the exact metadata shape. The owner's private checkpoint confirmed all eight generated fields, the three application fields, one IPA and no completed provenance manifest. No signing/profile success is inferred from those observations alone.

The corrected verifier requires the complete eight-field group for create/validate. It compares all six SDK values with the current pinned Flutter 3.47.5 machine identity, both build values with the expected IPA version/build, and retains the exact public backend, publishable-key classification and master=false checks. Unknown, duplicate, partial or mismatched metadata remains rejected. No definition value or credential is logged. Original three-field synthetic flag checks remain callable, but candidate create/validate cannot use that incomplete group.

The independent recheck helper uses the original build marker, original clean main SHA and exact CI, current tools/native context, version/build, IPA timestamp, signed identity/profile/certificate/expiry, callback and ATS/debug checks. It verifies original checkout/native/artifact/package inventories before and after. It never builds, installs or uploads. It writes a separately named `sko-testflight-provenance-rechecked.json` and `reverified-private.json`; the original failed record and IPA remain intact. The verification tool hash is recorded in the new private receipt. The external reviewed verifier is used without editing the original application's tracked source or rebasing main.

Twenty-three synthetic verifier tests and three preserved-checkpoint recheck tests pass locally. Real Mac revalidation and Apple upload are separate, still unconfirmed steps. Mock signing success is not actual Apple approval. A newer main, changed original work, changed IPA, missing build marker or mismatched SDK still stops the process. No production database, authentication, RLS or permission changes are part of this correction.

The first Mac recheck passed signature integrity, entitlements and distribution-profile checks but stopped at signer certificate extraction. The codesign option has an optional prefix argument; the prefix is now attached as `--extract-certificates=PREFIX`, not passed as a second code path. The extraction output is still required to match the certificate in the embedded profile. Apple codesign source declares optional_argument and supplies a default prefix only when that attached argument is absent. No certificate validation has been removed. The new argument-shape regression plus existing certificate-mismatch refusal pass locally; real Mac recheck remains required.
