# ログイン入口と本人確認の整理

基準 main 8f915a0。今回のUI整理は既存認証の利用範囲を広げない。

通常画面は登録済み方法のログインと初回利用案内を分ける。Googleボタンは既存platform判定と既登録membership確認を保ち、電話番号入力の見出しを明示。管理者初回登録と従業員登録QRの説明をまとめ、QRを単なる別ログイン方式と誤解しにくくする。既存のSMS登録可否・SMS復旧非対応・キャンセル・失敗・actor切替・完了callbackは維持する。

アカウント設定は「ログインと連絡先」「重要情報を開く本人確認」「ログイン方法の追加」の3区分。第2パスワードとFace IDを重要情報側へまとめ、Apple/Google/電話/メールの連携状態・連絡先表示と分ける。本人UID・既存会社・権限・パスワード・連携先を変更する操作を追加しない。「？」ヘルプと英訳を追補。

既存Googleログイン・アカウント状態/SDK・背景/actor/遅延応答の3testfiles19件成功。新しい実Apple/メールログイン・方法追加・電話所有確認・実Face ID・復旧が完成したという意味ではない。初回QRの期限/再利用に関する既#1245/#1247と同一本人連携/再認証の残工程を維持する。
