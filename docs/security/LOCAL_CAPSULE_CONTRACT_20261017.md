# Bounded personnel restoration preparation

This candidate is an offline **preflight**, not a restoration verifier or deployment tool. Its only subprocess is explicit PostgreSQL 17 `pg_restore --version`, `--list` or schema extraction with `--file`; no database process, connection, SQL execution, production credentials or migration application is used. Existing archive bytes are read only. Every output directory is new and private (0700/umask 077). Extracted SQL and errors may contain sensitive values and remain local; public output contains only scope/status and the private evidence location.

The existing two-table Master rehearsal is valid evidence for its narrow device/admin exercise only. It does not verify personnel/Auth/company/role/ACL recovery. A pg_dump archive does not by itself contain original cluster-wide CREATE ROLE/ALTER ROLE/role-membership definitions. Do not manufacture permissive roles or helper stubs to pass a test.

## Two separate possible restoration claims

1. **Bounded personnel subgraph:** extract dependency inventory privately, identify exact tables/types/functions/policies/triggers/roles/ACLs needed for canonical/legacy/direct personnel reads and existing save/decide paths. Include actual protected Auth IDs/provider mappings and Master/company membership/role invariants needed for preservation comparison. Retain exact function bodies and security attributes. An unrelated extension outside this subgraph need not block this limited claim. An unavailable extension *inside* the selected subgraph, an unresolved dependency or unknown original role/security attribute must stop it. No filtered reconstruction may be called a full database recovery.
2. **Full database recovery:** requires all archived dependencies/extensions and separately preserved original roles, plus external Auth/provider/settings/Edge/Storage configuration and appropriate bytes. Native Homebrew PostgreSQL cannot be assumed to support Supabase-only extensions. This broader claim remains unverified and is not demanded merely to inventory a bounded subgraph.

Before any archive execution, independently verify outbound isolation on the actual Mac. The preflight does not assume an undocumented macOS sandbox capability. A Unix socket and disabled TCP *listening* do not block functions/extensions from making outbound connections. Disable scheduled workers/preloads and all outbound mail/SMS/OAuth/notifications, and independently demonstrate the enforced network boundary. Unknown isolation means STOP, not a simulated success.

- Create a new disposable PG17 cluster and private Unix socket, no TCP listening, scrub inherited PG settings. Do not use Homebrew's default cluster, `brew services`, existing SKO databases or the production connection plan.
- Restore reviewed exact roles/security metadata and the chosen dependency subgraph. Preserve source owner/ACL/RLS/security-definer/search-path attributes; no `--no-owner`/`--no-privileges` shortcut for the ACL claim. Restore data before triggers/post-data; review side effects before enabling anything.
- Compare all protected restored rows internally, including administrator IDs/enabled states, company associations/roles and existing Auth/provider maps. Store snapshots locally, never print raw values or individual hashes. Include personnel/family and unrelated selected business data so unauthorized mutation cannot pass unnoticed.
- With the original baseline saved, run only reviewed `20261016104441`, `20261016113335`, `20261016120458` candidate SQL in a controlled local transaction, respecting original baseline guards. No generic db-push and no unrelated migrations.
- Use synthetic actors in the isolated restored environment to compare UI contracts/canonical RPC/legacy RPC/direct REST: self/admin/delegated ON legitimate paths; OFF manager/foreign/anonymous/account-restricted denial; separate registered OFF-manager approval authority remains. Restoration of the old baseline knowingly reopens the original leak; never treat it as an automatic safe production rollback.

Preflight exit 2 means inventory completed **with mandatory remaining gates**, not success. Exit 1 means inventory incomplete. Neither authorizes production RLS/roles/Auth/data changes or TestFlight safety approval.

## Separate read-only role/dependency capsule

`role_dependency_inventory.sql.review-only` is a catalog SELECT candidate, never automatically executed by the offline script. Its output is private. It collects dependency identities/owner ACLs and relevant role attributes/membership options, never passwords, role-setting values, Auth/business rows or function bodies. Original login password recovery is outside this capsule. Role attributes such as BYPASSRLS and LOGIN must be reviewed faithfully; do not convert them to permissive stand-ins. It does not create roles or memberships.

The graph follows recorded dependencies and reverse relation-owned policies/triggers/constraints/defaults/rules. It is deliberately conservative and can expand beyond the ultimately chosen restore subset. It is an inventory for human review, **not an executable pg_restore filter**. The pg_depend graph does not capture every reference in string-bodied SQL, PL/pgSQL or dynamic SQL; compare original private schema extraction and the exact existing regression fixtures before choosing the bounded subgraph. Never upload the private schema/archive here. A safe public report contains only result counts, missing dependency categories and explicit unverified gates; names/ACLs and sensitive extracted definitions stay on the Mac.

Policy-only `polroles` entries are included even when no table/function ACL mentions them. Required parent-role and membership-grantor relationships are followed; unrelated incoming members are intentionally not recursively enumerated (this is not a full cluster role backup). Function entries include identity arguments to distinguish overloads. Column ACLs, default ACLs, full sequence ownership/associated state, role settings/expiry and role password recovery are not completely inventoried by this SELECT. The original private schema extraction and a separately reviewed capsule must supply any of those required by the chosen subset. Do not claim that this inventory preserves every original role/ACL.

Validation at this source checkpoint: isolated PGlite executes the SELECT and includes a synthetic dependent policy. This does not establish native PG17/full Supabase catalog coverage, actual archive compatibility or real administrator restoration. Offline Python mock checks cover PG environment scrubbing, metadata parsing, private extraction, archive preservation, public secret exclusion and symlink refusal. No actual archive or production database was used in these checks.

## Operator-Mac private read-only collection candidate

`collect_private_capsule.py` is a separate candidate, not invoked by the offline helper. Root must review it before giving an operator an execution command. It statically parses only the five existing PG connection assignments from the already private operator plan; no shell evaluation, new credential entry or credential printing occurs. It permits only the exact project's Supabase direct hostname, or a Supabase pooler with the project-bound username; unknown host forms stop for review. psql is noninteractive (`-w`), startup-file-free (`-X`), SSL-required, bounded by connect/statement/lock/transaction timeouts and explicit `BEGIN READ ONLY`. The inherited PG environment is replaced. Schema-only pg_dump is additionally constrained by `default_transaction_read_only=on` and never restored.

Output is a new private local directory: current schema-only custom archive, limited role/dependency inventory, minimal before/after Master ID/enabled state, company IDs/membership roles, Auth user IDs and provider-name mappings, and local-only file checksums. No user password/hash/token, email, phone, Auth metadata or business-row content is selected by the invariant query. These selected values remain on the Mac and must not be pasted/uploaded. A comparison failure stops the candidate. Different files use independent read-only transactions: equality of the selected before/after invariants is not one shared database snapshot, proof of unchanged unrelated rows, or proof that another process made no temporary change.

This is preservation **collection**, not restored-data verification, complete role/ACL backup, provider-login testing or deployment approval. It intentionally exits 2 after collection to retain those gates. Private query errors may contain SQL/catalog details and remain local; public output reveals only status/type and the private evidence directory. The existing older data archive remains untouched. No production row or permission mutation exists in this candidate. Mock tests verify project binding/static parsing, read-only flags and transaction boundaries, noninteractive calls, unchanged plan bytes, private-only values and explicit unverified manifest fields; actual operator connection/archive collection has not run.
