# ルート出勤の表示・保存済み日報の読み取り修正

週間出勤表とカレンダーの勤務先表示は、保存済み勤怠に紐づくルート題名を優先する。複数ルートは順序を保持して連結し、元の現場名・勤怠数量・給与計算値は保持する。カレンダーでは題名全文をTextへ渡し、セル内で文字欠けを許容する。

月/日別の一覧は従来の `public.daily_reports` と、本人が保存した `private.route_visit_reports` を別の文書として列挙する。日付や現場名だけで統合しない。新規RPC `list_saved_route_visit_reports` は既存の訪問日報読取と同じ本人作成・所属・有効アカウント範囲を維持し、private表への直接参照は許可しない。スキップされた文書は除外する。社員を選んだ出勤表からは、その社員が含まれる日報へ絞り込む。

各行から既存のA4プレビューを開く。通常日報は一覧のIDと日付/現場を照合し、訪問日報は保存済み到着/移動の固定IDペアで読み取る。訪問証跡も同じペアに限定し、既存の写真読取を再利用する。印刷・共有/ファイル保存は既存プレビュー経路を使い、PDF名に日報IDを含めて同日の複数文書を区別する。月/日のZIP保存も各文書を保持する。

手書きサインのPDF描画は、現在の `{strokes: [...]}` 保存形式と旧配列の双方を受け取る。保存内容、署名API、確定状態、A4帳票配置は変更しない。

- Flutterの4件個別閲覧、アカウント変更拒否、署名描画、320px/文字1.3倍の週間/カレンダー題名テストを追加。ローカルFlutterは未実行、CI結果はPRに記録する。
- 本番RPC反映、Release上書き、実機印刷/ファイル保存は未実行。コード/隔離SQL成功を実機成功とは扱わない。
