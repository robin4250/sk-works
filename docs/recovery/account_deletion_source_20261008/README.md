# アカウント削除ソースの読取り保存（2026年10月8日）

公開準備のレビュー用バックアップです。実行・有効化・デプロイ用ではありません。

## 保存元と内容

Supabase プロジェクト `ztktgquxvcxcjxtluspu` のデプロイ済みソースを管理 API の読取り機能で取得しました。

- `account-deletion`：version 3、JWT 検証あり、6 モジュール。
- `account-deletion-worker`：version 2、JWT 検証あり、26 モジュール。
- 各 manifest に取得時のデプロイ情報と全ソースファイルの SHA-256 を記録しています。2つの配布物は独立して保存し、同名モジュールの差異も保持しました。
- `rpc_definitions_snapshot.sql` は上記ソースから呼ばれる関数名を対象に、Postgres カタログから取得した28定義と ACL の参照用スナップショットです。マイグレーションではありません。実行しないでください。関連する private/public の同名定義を含みます。

登録データ・削除要求・ジョブ・メール・認証セッション・資格情報・環境変数の値は取得していません。ソース中の環境変数名は設定値ではありません。

## 現在の停止条件を維持

取得時のソースを変更せず、次の固定ガードを保持しています。

- `intakeReleaseVerified = false`
- `lifecycleReleaseVerified = false`
- `officialDocumentRetentionFinalized: false`（両配布物）

Edge Function の管理表示が ACTIVE でも、削除受付・ワーカーの公開準備が完了したことを意味しません。保存は機能を有効にしません。

## 公開前に残る確認

保存対象帳票の保持方針、本人確認とセッション失効、Google 連携解除、Storage の所有権・削除後アクセス、完了通知の重複防止、実配備の権限制御を、隔離したテスト環境とレビューで確認する必要があります。このバックアップのみで削除処理を承認・公開可能とは判断できません。

今回、削除・受付・通知・メールのエンドポイントは呼び出していません。デプロイ、権限、設定、登録データ、DB 関数は変更していません。取得時のソース定義は信頼済みの実行指示ではなく、レビュー対象として扱います。

## 検証

全32モジュールの保存内容を取得結果のバイト列と一致させ、manifest の SHA-256 と照合しました。既存リポジトリの secret scan と同等の6パターンに、長い secret/token/password/API key の固定値検査を追加し、保存物全体で検出なしを確認しました。30個の `.mjs` は実行せず `node --check` の構文チェックに合格し、32モジュールの全ローカル相対 import が保存先に存在することを確認しました。固定ガード4箇所も false のままです。
