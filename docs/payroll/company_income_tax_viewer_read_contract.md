# Company income-tax metadata and PDF viewer read — staged source

This additive migration checks the exact current metadata reader, admin guard, registration function and owner/admin PDF access helper bodies/config, plus the two existing SELECT policy expressions, roles and permissive/restrictive types. Unknown source differences fail before changes. It leaves registration, upload, verification, common-data approval, raw grants, bucket configuration and non-SELECT Storage policies unchanged. Production application is not performed.

Metadata reading requires authenticated same-company owner/admin/viewer membership, the existing account-access guard returning true and a live company row. The JSON gains authoritative can_edit. Owner/admin receive true and their complete original result; viewer receives false, table/selected metadata with registered_by omitted, and history=[] while registered_at, year/kind/period/path/hash and verification flags stay visible. A nonmember whose UI defaults to viewer is denied. No invoice, personal pay, family or bank access is added.

PDF upload keeps the existing owner/admin helper. Only the two dedicated SELECT policies use the new read helper. Owner/admin retain their existing access to valid same-company paths. Viewer paths must match that live company's current document metadata or a before/after storage_path in its registration history. This retains older registered document versions and prior years without exposing audit actor IDs or allowing unregistered orphan files. Foreign-company history cannot authorize a current-company orphan.

The dedicated restrictive guard remains effective beside unrelated broad permissive policies. Same-company registered PDF object get/info/head/sign operations are permitted; list/list_v2/sign_many, upload, signed upload, overwrite, update/delete and anonymous operations remain outside the contract. Malformed UUID/path/version/hash inputs fail closed. Other bucket policies remain unchanged. Reading a PDF does not verify its bytes, make it official, prepare calculation rules, approve sharing or select an unverified upload for payroll.

The isolated PGlite fixture passes owner/admin result equality apart from can_edit, unchanged admin/write/helper hashes and ACLs, unchanged non-SELECT policy expressions, actual version1→2 registration history PDF access, prior-year access, actor projection, scoped viewer reads and all write/list/orphan/cross-company/account/anonymous refusals. Owner/admin can still upload/register a new version, which remains unverified with selected=null. Company deletion blocks new reads even with stale membership and retained logical history. The original metadata and Storage full regression harnesses run separately unchanged.

A dedicated empty-database PostgreSQL 17 job is prepared for the same exact source and policy tests; native results are pending CI. The Storage tables, operation setting and membership/account guard are synthetic fixture prerequisites. These tests are not actual Storage HTTP upload/download bytes, signed-URL issuance, JWT/account session proof, official PDF identity verification or production schema/advisor verification. The UI retains its existing single-file 600-second signed URL behavior without persisting that URL as document identity.
