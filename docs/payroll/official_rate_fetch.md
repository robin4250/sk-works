# 公式料率の取得と明示適用

現在設定を保持したまま、会社管理者が「最新の公式料率を取得」を押し、保険適用開始月・給与対象開始月・給与支払月を入力する。公式資料の納付月は給与支払月にコピーしない。取得後は既存の現在値／候補比較を表示し、項目別の確認・版照合・適用を使用する。閲覧者は保存値と候補の閲覧のみ。

Edge Function `fetch-company-payroll-rates` は本人JWTをAuthで検証し、既存料率読取RPCの会社管理権限と会社条件を確認する。公式HTMLの許可済URLだけを取得し、年度、47県、一般被保険者、雇用保険の3事業区分・別負担率を解析する。取得した実本文SHA-256と出典を候補に保存する。会社条件を再確認した後、service専用の候補登録RPCを呼ぶ。クライアント送信の料率・URLは受け付けない。候補取得は現在設定・給与を変更しない。

登録RPCは会社lock→料率registry lockの順序を維持し、管理者・退会制限・会社条件versionを再確認する。候補全件を一transactionで検証・登録する。変更前の候補は残す。設定の更新は既存の明示適用APIだけで行う。通信結果不明の再取得で候補が増える場合はあるが、給与・設定の二重更新は起こさない。

対応資料は2026年4〜12月時点の協会けんぽ（健康・介護・支援金）、厚生年金、雇用保険。将来年度は古い値を最新扱いせず停止する。組合等には協会けんぽの値を流用せず、年金・雇用のみ取得して案内する。会社条件の未設定、解析失敗、通信失敗では現在設定を維持する。所得税は定率ではなく既存の2026月額税額表計算を使用し、この取得の対象にしない。

会社で採用する保険月は各公式開始月以降・現在月以前。給与月との差は前後1月以内、給与支払月は給与対象月または翌月に限定する。それ以外の支給周期は自動取得の月対応を推測せず、既存の個別確認が必要。

導入はmigration `20261010041129_official_payroll_rate_candidates.sql` → Edge Function → Flutter Releaseの順。既存会社条件・実税率・従業員条件は自動で登録しない。関数はuser JWT検証を有効にして配置し、サーバー既存Supabase環境変数を使用する。追加有料サービス・外部AI解析・Web開発は含まない。

検証は公式HTML parser、認証済handler、SQL実migrationのservice権限/会社条件競合/batch rollback/通常適用、Flutterの候補表示/失敗時保持/閲覧者を分けて行う。本番の取得・適用操作とRelease実機確認は導入後の確認対象。
