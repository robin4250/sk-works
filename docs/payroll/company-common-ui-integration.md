# 社内共通手当 UI 接続契約

2026-10-15 ユーザー指定。給与保存・計算・DBはMac Codex担当を維持。

## 作成済み UI

- `PayrollReviewPage.onOpenCommonAllowances`：税率設定と個別給料設定の間の入口。3つともExpanded、48px高、間隔10px。
- `CompanyCommonPayrollPage`：日給/時給/月給、支給/控除、区切り線、共通支給/共通控除。
- 給与形態はdaily/hourly/monthly、支給単位はhour/day/monthで別の軸。
- 給与形態ごとに既存PayrollUnitItemEditorを保持し、切替で未保存入力を破棄しない。
- onRegister未接続なら編集・保存を無効化し、個別反映準備中を表示。

## Mac担当で接続が必要

1. 会社単位の共通設定を、給与形態・支給/控除・単位・安定項目ID・版で保存する契約を決める。既存3枠との二重登録は避ける。
2. 管理者は編集、閲覧者は閲覧のみ。一般/サブ管理者の設定入口権限を拡張しない。サーバーでも会社・権限を検証。
3. 該当給与形態の個別給料設定に共通項目を表示する。個別項目を維持し、同一共通IDは二重計上しない。名称を識別子にしない。
4. 更新/廃止、個別例外、給与形態変更の適用時点を実装し、確定済み過去明細を遡及変更しない。
5. 保存成功応答を検証してから成功表示する。競合・通信不明時は入力保持し、保存済みと扱わない。
6. 給料一覧の既存admin/viewer入口条件の内側でcallbackを接続し、第2認証と既存機能ON/OFFを保持。
7. 実接続後にメニューの「？」を3ボタン/2段タブ/共通反映の説明へ更新する。

このPRは画面部品と入口callbackの準備のみ。app_v2の本番導線、保存、DB、給与計算、個別反映を変更していない。未接続画面を本番完成として公開しない。
