# 個別給与の単位別支給・控除（ベータ版）

個別給与設定の「単位別の支給・控除」から開き、支給／控除、時間／日にち／月を選びます。登録は全6区分を同時保存します。給与形態の日給／時給／月給とは別の設定です。旧来の直接入力金額・既存手当・税・保険料はそのまま保持します。

時間数は対象月に明示入力するか、正式登録済み残業・早出・夜間時間を明示選択します。人工×8時間や出退勤の差から一般労働時間を推定しません。手入力0時間も、実際に0を入力した時だけ0として保存します。月ごとの未入力はnullのまま計算保留となり、確定できません。

日にち単位は正式勤怠の実出勤日数（base_man_daysが正の distinct work_date）です。同日の複数現場を複数日には数えません。人工数量ではありません。月単位は正規の月次給与期間につき1回で、中途入退社の日割りは推定しません。円額は単価×数量を項目ごとに四捨五入します。

単位条件は選んだ月から有効な履歴として保存し、月別の明示時間数は別に保存します。過去の月を切り替えた際は未登録入力を破棄する確認があります。項目UUID・保存version・会社／社員／月のscopeを検証します。月単位条件を保存しても未承認の日報を正式勤怠とみなしません。

private条件テーブルの直接アクセスは禁止し、既存payroll_settings_allowedとaccount_access_allowedで許された本人認証のread／save RPCだけを利用します。確定済み・手動給与は変更不可です。旧直接額と単位結果を一度だけ合算し、既存税計算と確定検証に同じ結果を渡します。税率数値・認証・既存権限ルールは変更しません。

MigrationはSupabase CLI migration newで生成しました。本番適用前に3関数のmd5前提一致を検証します。本番への適用・iPhone検証は別工程です。旧サーバーや取得失敗は設定不可として表示し、保存できたように扱いません。日報の手当数量入力へは接続していません。この画面の実時間数量と既存日報数量は混同しません。

検証：PGlite 0.3.14で既存給与／税／確定snapshotの実SQLを読み込み、6区分保存・再読・旧直接額保持・数量×単価・同日重複除外・正式時間source・不足数量null／blocked・権限・版競合・本物の確定操作と保存済み明細不変を確認。Flutter widget／Repository検査はCIで別途確認します。

## 翌月以降の継続表示

給与の確認月を翌月・翌々月へ移しても、現在の個別手当の名称・単価を「継続中の手当」として表示します。毎月の再登録は不要です。日単位の手当は各月の実際に選択された勤務日数で計算します。単位別の追加条件は既存の starts_on 以下の最新履歴を利用し、月別時間数は複製しません。

元からある worker 設定には未来の適用開始履歴がないため、翌月画面の継続表示は読取専用です。翌月からその原本を書き換えたり単位別保存へ複製しません。現在月へ戻ると既存の編集・保存を使えます。過去月・確定済み・履歴欠落には現在の値を代用しません。

検証は新しい Flutter 月移動回帰と既存の source-bound PostgreSQL17 fixture を拡張した継続給与テストを remote CI で実行します。ローカル Flutter は実行しません。実機確認は別工程です。
