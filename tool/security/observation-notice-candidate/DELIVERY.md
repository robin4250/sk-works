# Isolated authenticated-observation delivery candidate

This draft connects an already authenticated collector evidence insert to a durable, private outbox in the same transaction. Enabled configuration pins collector, company, Master recipient and revision from administrator-controlled storage, never from event bytes. Publishing an event is service-authorized and locks its row, revalidates the current Master/company role, configuration and existing HMAC evidence, then atomically records a private in-app inbox item and audit. Repeated publication returns the existing state. No IP, request body, token, correlation key or personal data is copied into the inbox.

This is not deployed and defaults OFF. During OFF, collector events deliberately do not create notice entries: no claim of monitoring coverage or replay/backfill is made. Any held state needs a separately audited recovery design. A candidate public read function is restricted to authenticated callers and checks a live session, current Master/company role, and the existing one-use collector-read proof. Publication has no public wrapper or service GRANT. No hosted endpoint, read-mark/review action, UI, independent audit anchor, retention or real-host recovery is connected. Worker-side outbox retries are separate and already tested. Before enabling, verify Master-session+operation-proof gated listing against actual GoTrue and define explicit read/review, test race-safe Master revocation and config changes, backlog/backfill and fail-safe coverage, bounds/retention, catalog/body pinning and safe unused restore. Run actual collector SQL, genuine GoTrue and Postgres concurrency tests, then real host/notification/iPhone tests. A failed or unknown acknowledgement must not duplicate records or erase evidence. No production data, keys or actual notifications are used.
