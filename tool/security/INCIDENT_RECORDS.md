# Sanitized incident records / collection window (beta)

This implements an offline synthetic collection window and a separately gated operator-import store. It does not connect the decoy to production, provision ingress monitoring, obtain real actor/session/IP identity or send external notifications. All source provenance is explicitly `synthetic_fixture`; a pseudonym is a synthetic shared source, never proof of a person. Unknown ingress/source is `unavailable`. Client proxy headers are ignored, not trusted metadata.

Collector bounds: 128 retained events, 100 incidents, maximum one-hour retention; default before/after 30 seconds with two-minute retention. Fixed enum/timestamp/generation only. Same event IDs are rejected within the retained event buffer. Out-of-order late events are sorted by timestamp/event ID. Source rotation starts a separate correlation epoch. Correlation only joins the bounded overlapping window. Raw source pseudonyms, bodies, headers and identities never leave reports. Regression/unavailable clock fails closed. Missing initial coverage, capacity eviction, expired evidence and collection not yet finished are explicit. `complete` means the synthetic collector window elapsed without known drops, not proof of a real uninterrupted ingress feed.

The import RPC requires the authenticated enabled master, permitted account, exactly one company membership, and saves to that actor/company only. No company or recipient override. Private tables have RLS and no direct grants to anon/authenticated/service_role. Public RPCs are invoker wrappers; privileged implementations are private with explicit grants. No existing auth functions or tables are rewritten.

`save_master_security_incident(p_record jsonb,p_record_version integer default 1)` imports a finalized sanitized snapshot, including explicit empty evidence when coverage is missing. Maximum 100 incidents per owner/company, 16 immutable versions per incident, 64KiB input and 128 events per version, seven-day record expiry. Exact JSON fields/types/enums are validated. Same ID/version/content is idempotent; changed content conflicts. Subsequent versions must advance by one and preserve correlation/detection window. Prior versions remain unchanged. Notification insertion and the initial unique incident outbox are in the same transaction as save; failure rolls back the record. Only the current master actor receives the existing in-app notification; no broadcasts or LINE/email.

`master_security_incidents()` returns `{version:1,incidents:[...]}` with latest versions, server save timestamp/source provenance/reason code/synthetic correlation confidence and append-only imported-version audit. Status remains `detected`, never automatic `confirmed`. Confirm/dismiss investigation mutations, live correlation acquisition, verified actor/session identity, ongoing public transport and important-continuation notification policy are not implemented here. A later independently reviewed change can add those without reclassifying synthetic evidence as actual attacks.

Report signature/integrity is not asserted by this store. The isolated signed controller ledger from #1013 is separate; no production key is available to the decoy. JSON/PDF must preserve the same incident/version and label collection limitations; a digest alone does not prove authenticity. Full restart durable collection and source-key rotation remain deployment gates.

Validation: synthetic collector tests and PGlite SQL role/grant/company/identity/metadata/version/atomic-notification tests. Dedicated CI installs the exact locked PGlite fixture dependency and runs both, without production credentials. PGlite verifies SQL semantics but does not prove real PostgREST JWT behavior or multi-connection PostgreSQL locks. Root performs production review/deploy only after final CI and prerequisite checks.
