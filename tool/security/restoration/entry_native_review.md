# Native PostgreSQL synthetic probe

The original hash-verified `entry_isolation.py` remains unchanged. The native-only variant adds exactly `(allow ipc-sysv-shm)` and `(allow ipc-sysv-sem)` after its existing rules. The same-host IPv4/IPv6 outbound denial, outside-write denial, inside-write and exact UNIX socket checks run again under this variant before initdb. No OS global settings or existing clusters are changed.

Observed CI: original native profile blocked PostgreSQL 17 initdb bootstrap at shmget(size=56). PostgreSQL 17 `src/backend/port/sysv_shmem.c` explains that mmap still keeps a small System V header for data-directory/process interlock: https://github.com/postgres/postgres/blob/REL_17_STABLE/src/backend/port/sysv_shmem.c . `shared_memory_type=mmap` does not remove this requirement. Official kernel-resource documentation: https://www.postgresql.org/docs/17/kernel-resources.html .

The IPC allowance is process-scoped but not restricted to one SysV key. Existing OS permissions still apply; this is not a separate IPC namespace, and does not prove isolation from all same-user IPC. No IPC/message wildcard, network allowance or filesystem write expansion is added. If further IPC is refused, stop and review rather than broaden automatically.

Only fixed synthetic SQL is allowed here. Archives, credentials, production connections, extension SQL and arbitrary restored functions are not used. File-read remains broad from the base policy. Even a successful native roundtrip is NOT permission to run a real archive and NOT full restoration/current-data recovery proof. A later archive step requires separate least-read roots/dependency review, current data/time-gap protection and operator approval under the project rules.

The next exact CI head e80630c passed source checks but initdb was refused at `semctl(..., SETVAL, ...)`: macOS PostgreSQL uses System V semaphores (`src/backend/port/sysv_sema.c`, https://github.com/postgres/postgres/blob/REL_17_STABLE/src/backend/port/sysv_sema.c ). The native-only variant therefore permits exactly the additional semaphore operation class, not all IPC. This shares the same no-private-IPC-namespace limitation above. Shutdown is only marked complete after pg_ctl status returns 3; other statuses retain the finally stop attempt. Real native success remains pending.
